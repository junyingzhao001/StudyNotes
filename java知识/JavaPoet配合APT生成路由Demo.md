# JavaPoet 配合 APT 生成路由 Demo

## 1、javapoet是什么有什么用

JavaPoet 是由 Square 公司开发的一个用于生成 `.java` 源文件的 Java API。在编写注解处理器（Annotation Processors）或者需要基于元数据生成代码时，它几乎是业界标准。

相比于手动拼接字符串，JavaPoet 能够自动处理 **导包（Import）**、**分号**、**大括号** 以及 **缩进**，极大地降低了出错率。

## 2、核心API

### 2.1、API

| 类名 | 作用 | 对应 Java 元素 |
| --- | --- | --- |
| MethodSpec | 生成方法 | 构造函数、普通方法 |
| FieldSpec | 生成变量 | 成员变量、常量 |
| TypeSpec | 生成类型 | 类、接口、枚举、注解 |
| JavaFile | 生成文件 | 包含包名、导包信息和代码主体 |

### 2.2、占位符详解

在 JavaPoet 中，我们不使用传统的 `%s`，而是使用其特有的占位符：

**`$S` (String)**：字符串。会自动加上双引号。

**`$T` (Type)**：类型。会自动处理 `import`。传入 `ClassName` 或 `Class` 对象。

**`$L` (Literal)**：字面量。直接把值填进去（如数字、原始代码片段）。

**`$N` (Name)**：引用另一个 JavaPoet 对象的名字（如方法名、变量名）。

## 3、使用方法

### 3.1、导入依赖

```text
implementation 'com.squareup:javapoet:1.13.0'
```

### 3.2、生成代码的逻辑

```java
import com.squareup.javapoet.*;
import javax.lang.model.element.Modifier;
import java.io.IOException;
import java.util.Date;

public class JavaPoetGuide {
    public static void main(String[] args) throws IOException {

        // 1. 创建方法: main
        MethodSpec main = MethodSpec.methodBuilder("main")
                .addModifiers(Modifier.PUBLIC, Modifier.STATIC)
                .returns(void.class)
                .addParameter(String[].class, "args")
                // 使用 $T 自动导包，使用 $S 自动加引号
                .addStatement("$T.out.println($S)", System.class, "Hello, JavaPoet!")
                .build();

        // 2. 创建成员变量: private String name;
        FieldSpec nameField = FieldSpec.builder(String.class, "userName")
                .addModifiers(Modifier.PRIVATE, Modifier.FINAL)
                .initializer("$S", "DefaultUser")
                .build();

        // 3. 创建类: HelloWorld
        TypeSpec helloWorld = TypeSpec.classBuilder("HelloWorld")
                .addModifiers(Modifier.PUBLIC)
                .addField(nameField)
                .addMethod(main)
                .addJavadoc("This class was generated by JavaPoet. Do not edit!\n")
                .build();

        // 4. 生成文件并输出到控制台（实际使用时通常写入文件路径）
        JavaFile javaFile = JavaFile.builder("com.example.generated", helloWorld)
                .build();

        javaFile.writeTo(System.out);
    }
}
```

## 4、APT (Annotation Processing Tool)简介

### 4.1、简介

APT 是一种编译期技术，通过扫描源码中的注解，在编译阶段生成辅助代码或做校验，避免运行期反射，提升性能和安全性。在 Android 中广泛用于路由、ORM、依赖注入等框架。

核心是注解，和注解处理器

### 4.2、案例

注解

```java
@Target(ElementType.TYPE)
@Retention(RetentionPolicy.SOURCE)
public @interface Route {
    String path();
}
```

注解处理器

```typescript
@AutoService(Processor.class)
public class RouteProcessor extends AbstractProcessor {

    @Override
    public boolean process(
        Set<? extends TypeElement> annotations,
        RoundEnvironment roundEnv
    ) {
        // 扫描注解 + 生成代码
        return true;
    }
}
```

### **5.3、添加代码**

#### 5.3.1、注解：

```java
package com.example.annotations;

import java.lang.annotation.ElementType;
import java.lang.annotation.Retention;
import java.lang.annotation.RetentionPolicy;
import java.lang.annotation.Target;

@Target(ElementType.TYPE)
@Retention(RetentionPolicy.SOURCE)
public @interface Route {
    String path();
}
```

#### 5.3.2、注解处理器：

```java
package com.example.processor;
import com.example.annotations.Route;
import com.google.auto.service.AutoService;
import com.squareup.javapoet.ClassName;
import com.squareup.javapoet.JavaFile;
import com.squareup.javapoet.MethodSpec;
import com.squareup.javapoet.TypeSpec;
import java.io.IOException;
import java.util.Set;
import javax.annotation.processing.AbstractProcessor;
import javax.annotation.processing.Processor;
import javax.annotation.processing.RoundEnvironment;
import javax.annotation.processing.SupportedAnnotationTypes;
import javax.annotation.processing.SupportedSourceVersion;
import javax.lang.model.SourceVersion;
import javax.lang.model.element.Element;
import javax.lang.model.element.Modifier;
import javax.lang.model.element.TypeElement;

@AutoService(Processor.class)
// 1. 必须精准指向你的注解类（包名+类名）
@SupportedAnnotationTypes("com.example.annotations.Route")
// 2. 匹配你项目的 Java 版本（通常是 RELEASE_8 或 RELEASE_11）
@SupportedSourceVersion(SourceVersion.RELEASE_11)
public class RouteProcessor extends AbstractProcessor {
    @Override
    public boolean process(Set<? extends TypeElement> annotations, RoundEnvironment roundEnv) {
        for (Element element : roundEnv.getElementsAnnotatedWith(Route.class)) {
            TypeElement typeElement = (TypeElement) element;
            generateRouterCode(typeElement);
        }
//        processingEnv.getMessager().printMessage(Diagnostic.Kind.ERROR, "======= 处理器正在运行 =======");
        return true;
    }

    private void generateRouterCode(TypeElement typeElement) {
        System.out.println("generateRouterCode............");
        // 获取 Activity 的类名
        ClassName activityClass = ClassName.get(typeElement);
        // 构建生成类的类名：Activity名 + "Router"
        String fileName = typeElement.getSimpleName() + "Router";

        // 获取 Android 系统的 Context 和 Intent 类名
        ClassName contextClass = ClassName.get("android.content", "Context");
        ClassName intentClass = ClassName.get("android.content", "Intent");

        // 构建方法：public static void launch(Context context)
        MethodSpec launchMethod = MethodSpec.methodBuilder("launch")
                .addModifiers(Modifier.PUBLIC, Modifier.STATIC)
                .addParameter(contextClass, "context")
                .addStatement("$T intent = new $T(context, $T.class)", intentClass, intentClass, activityClass)
                .addStatement("context.startActivity(intent)")
                .build();

        // 构建类
        TypeSpec routerClass = TypeSpec.classBuilder(fileName)
                .addModifiers(Modifier.PUBLIC, Modifier.FINAL)
                .addMethod(launchMethod)
                .build();

        // 写入包名（与 Activity 相同）
        String packageName = processingEnv.getElementUtils().getPackageOf(typeElement).getQualifiedName().toString();
        try {
            JavaFile.builder(packageName, routerClass).build().writeTo(processingEnv.getFiler());
        } catch (IOException e) { e.printStackTrace(); }
    }
}
```

## 6、@AutoService(Processor.class)是否是必须的

不是

因为 @AutoService 不是必须的，它只是帮你自动生成 SPI 注册文件。  
这个项目是**手动写了 SPI 文件**，所以照样能被 Java 注解处理器发现。

apt/src/main/resources/META-INF/services/javax.annotation.processing.Processor 

内容只有需要写一行：

```kotlin
com.therouter.apt.TheRouterAnnotationProcessor
```

这就是标准 JSR-269 的注册方式。编译器会从 META-INF/services/javax.annotation.processing.Processor 里读取处理器实现类，所以即使没有 AutoService也完全能正常工作。

你可以把两种方式理解成：

- @AutoService：自动生成 META-INF/services/...
- 手写 META-INF/services/...：自己注册，效果一样

## 7、注解相关

Java 注解很多，适合分两层理解：

1、Java 自带通用注解

2、自定义业务注解

### **7.1、Java 常见内置注解**

最常用的是这些：

- @Override  
作用：标记“这是重写父类/接口方法”。写错方法签名时，编译器会报错。
- @Deprecated  
作用：标记“这个类/方法/字段已过时，不建议再用”。
- @SuppressWarnings("xxx")  
作用：压制编译器警告，比如 unchecked、deprecation。
- @FunctionalInterface  
作用：标记函数式接口，只允许一个抽象方法。
- @SafeVarargs  
作用：告诉编译器“这个可变参数泛型用法是安全的”。
- @Native  
作用：标记常量字段可被 native 层引用，比较少见。

### **7.2、元注解：注解的注解**

这些是“定义自定义注解时”最常用的：

- @Target  
作用：限制注解能写在哪。  
常见值：ElementType.TYPE：（类、接口、枚举），METHOD，FIELD，PARAMETER，CONSTRUCTOR，LOCAL_VARIABLE，ANNOTATION_TYPE，PACKAGE，TYPE_PARAMETER，TYPE_USE
- @Retention  
作用：定义注解保留到什么时候。  
常见值：SOURCE：只在源码里，编译后丢掉CLASS：保留到 class 文件，运行时默认拿不到RUNTIME：运行时可通过反射读取
- @Documented  
作用：生成 Javadoc 时带上这个注解说明。
- @Inherited  
作用：类上的注解可被子类继承。  
注意：只对类继承有效，对方法/字段无效。
- @Repeatable  
作用：允许同一个注解在同一个目标上写多次。

案例：

```java
@Target(ElementType.TYPE)
@Retention(RetentionPolicy.RUNTIME)
public @interface Route {
    String path();
}
```

### **7.3、自定义注解有什么用**

主要有两大类用途：

- **运行时使用**  
例子：Spring、JUnit、Android 路由框架用反射读取注解。
- **编译使用**  
例子：APT/KSP 根据 @Route、@Autowired 生成代码。

### **7.4、AbstractProcessor 是干嘛的**

AbstractProcessor 是 Java 注解处理器的基类，属于 JSR-269 APT 体系。

作用是：

**在编译期扫描注解并生成代码、校验代码。**

典型用途：

- 生成路由表
- 生成 DI 代码
- 生成序列化代码
- 生成数据库映射代码
- 做编译期校验

### **7.5、AbstractProcessor 常见生命周期/回调方法**

最重要的是这些：

- init(ProcessingEnvironment processingEnv)  
作用：处理器初始化时调用一次。  
一般在这里拿工具类：MessagerFilerElementsTypes
- getSupportedAnnotationTypes()  
作用：告诉编译器，这个处理器支持哪些注解。
- getSupportedSourceVersion()  
作用：告诉编译器，支持哪个 Java 版本。
- getSupportedOptions()  
作用：声明可接收的编译参数，比如 -Akey=value。
- process(Set<? extends TypeElement> annotations, RoundEnvironment roundEnv)  
作用：**核心回调**。  
编译器每一轮处理都会调用它。  
你可以在这里：找到被注解标记的元素做校验生成代码

### **7.6、process() 为什么会被调用多轮**

APT 不是只跑一轮，原因是：

- 这一轮你生成了新源码
- 编译器会继续编译这些新源码
- 然后再进入下一轮处理

所以注解处理通常是“round-based”。

你会经常看到这种写法：

```typescript
private boolean isProcess = false;

@Override
public boolean process(Set<? extends TypeElement> annotations, RoundEnvironment roundEnv) {
    if (!isProcess) {
        isProcess = true;
        // 真正处理
    }
    return true;
}
```

### **7.7、一个典型处理流程**

以 @Route 为例，处理器一般这样工作：

编译器发现源码里有 @Route

调用 process()

处理器从 roundEnv 里取出所有带 @Route 的类

校验它们是否合法

生成 RouterMap\_\_TheRouter\_\_xxx

编译器继续编译生成出来的源码

### **7.8、process() 里常用的 API**

roundEnv.getElementsAnnotatedWith(Route.class)  
获取所有带某注解的元素

element.getKind()  
判断元素是类、方法、字段等

element.getSimpleName()  
获取名字

element.asType()  
获取类型

processingEnv.getFiler()  
生成文件

processingEnv.getMessager()  
打印编译错误/警告

processingEnv.getElementUtils()  
元素工具

processingEnv.getTypeUtils()  
类型工具

### **7.9、process() 返回值是什么意思**

返回 true  
表示“这些注解我处理掉了，别的处理器别再处理”

返回 false  
表示“我没完全处理，其他处理器还可以继续处理”

### **7.10、你可以把 AbstractProcessor 生命周期记成这张小表**

init()  
初始化处理器，只调一次

getSupportedAnnotationTypes()  
声明支持哪些注解

getSupportedSourceVersion()  
声明支持的源码版本

getSupportedOptions()  
声明支持的编译参数

process()  
每轮编译处理时调用，核心逻辑都在这里
