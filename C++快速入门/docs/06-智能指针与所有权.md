# 06 · 智能指针与所有权

[返回学习地图](../README.md) · [下一篇：string与STL容器](07-string与STL容器.md)

## 本篇目标

会使用 make_unique，区分独占所有权、共享所有权和借用。

## 学习作用

减少 new/delete 配对错误，读懂对象由谁负责销毁。

## 核心知识

`std::unique_ptr<T>` 独占一个动态对象，自己销毁时释放它；不可复制，可以移动。`std::make_unique<T>(参数)` 同时创建对象并返回拥有它的智能指针。

`std::move(x)` 把表达式转换成可被移动的形式，真正的转移由目标类型的移动操作完成。unique_ptr 移动后源指针为空；不要把这一保证推广到所有类型。

这一篇只需要先记住：unique_ptr 不能复制，想把唯一所有权交给另一个变量时写 `std::move(owner)`。第 09 篇会完整解释普通对象的移动和返回值优化。

`.get()` 返回借用的原始指针，不转移所有权，不能交给另一个智能指针重新拥有，也不能手动 delete。若对象只需在当前作用域存在，直接局部变量通常就够了，不需要为了使用智能指针而分配到堆上。

确实有多个独立拥有者时才考虑 `shared_ptr`；它的引用计数不等于被管理对象线程安全。两个 shared_ptr 相互拥有会形成循环，需用 `weak_ptr` 表示其中的非拥有关系，并用 `lock()` 尝试取得临时共享所有权。

## 先按意图选择

| 想表达的关系 | 推荐写法 |
| --- | --- |
| 当前作用域直接拥有 | `T value`，优先考虑 |
| 只读借用 | `const T&` |
| 修改借用 | `T&` |
| 可空借用 | `T*` / `const T*` |
| 动态对象只有一个所有者 | `std::unique_ptr<T>` |
| 业务上确有多个独立所有者 | `std::shared_ptr<T>` |
| 观察 shared_ptr 对象但不参与拥有 | `std::weak_ptr<T>` |

Java 引用由 GC 追踪，不直接编码“谁拥有对象”。unique_ptr 在类型层面表达唯一所有者，这是 Java 没有的直接对应物。不要因为 Java 里常复制对象引用，就把 C++ 的 shared_ptr 当默认选择。

## 可运行 demo

源码：[demos/06.cpp](../demos/06.cpp)。从 `C++快速入门` 目录执行：

```bash
mkdir -p build
c++ -std=c++17 -Wall -Wextra -Wpedantic -g demos/06.cpp -o build/demo_06
./build/demo_06
```

```cpp
#include <iostream>
#include <memory>
#include <string>
#include <utility>

struct Task {
    explicit Task(const std::string& value) : title(value) {}
    std::string title;
};

void printTask(const Task* task) { // 仅借用
    if (task) std::cout << task->title << '\n';
}

int main() {
    auto owner = std::make_unique<Task>("Learn ownership");
    printTask(owner.get());
    auto nextOwner = std::move(owner);
    std::cout << std::boolalpha << "old owner empty: " << (owner == nullptr) << '\n';
    printTask(nextOwner.get());
}
```

预期输出：

```text
Learn ownership
old owner empty: true
Learn ownership
```

## 移动前后状态

| 时刻 | owner | nextOwner | Task 是否存活 |
| --- | --- | --- | --- |
| make_unique 后 | 拥有 Task | 尚未创建 | 是 |
| `std::move(owner)` 后 | 空 | 拥有同一个 Task | 是 |
| main 结束 | 销毁空指针 | 析构并释放 Task | 否 |

`std::boolalpha` 只改变 bool 的输出格式，让 true/false 代替 1/0，不影响指针状态。

## 常见坑

`p->field` 相当于 `(*p).field`。unique_ptr 转移后，之前借出的对象指针是否还有效取决于对象是否仍存活；不要让借用逃出所有者的生命周期。

移动 unique_ptr 只转移所有权，不会搬动它所管理的 Task。因此移动前 `owner.get()` 得到的借用指针，在 nextOwner 继续拥有该 Task 时仍指向同一对象；nextOwner reset 或析构后，这个借用才悬空。

## 动手练习

1. 预测：移动后分别对 owner.get() 和 nextOwner.get() 调用 printTask 会发生什么？函数本身能处理空指针。
2. 修改：写 `std::unique_ptr<Task> makeTask(const std::string& title)`，从函数返回所有者。
3. 独立：写 `consumeTask(std::unique_ptr<Task> task)` 表达接管所有权，并从 main 用 move 调用；说明调用后原 owner 的状态。

## 完成标准

能给一个动态对象标出唯一所有者，并说清它何时销毁。
