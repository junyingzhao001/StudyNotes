# 00 · 先建立 C++ 心智模型

[返回学习地图](../README.md) · [下一篇：编译运行与程序结构](01-编译运行与程序结构.md)

## 先说结论

C++ 中看起来相近的变量声明，可能分别表示一个新对象、一个独立副本、一个别名或一个地址。Java 背景学习者最需要先切换的就是这套对象模型。

读完本篇，你能看到一行变量声明就判断：有没有创建新对象、修改会落到哪里、谁负责让对象继续存活。这个能力会直接帮助你理解后面的引用、指针、容器、析构和智能指针。

## 问题：不能把 Java 对象赋值直接套到 C++

Java 中，`Note original = new Note("hello"); Note another = original;` 通常让 original 和 another 指向同一个 Note。C++ 的普通对象变量默认更接近“直接装着对象本身”。对本篇这个可复制的 Note，`Note another = original;` 会初始化一个新的 Note，两个 Note 各自拥有自己的 string。

具体类型可以禁止复制，也可以自定义复制行为。因此不要把“赋值一定深拷贝”推广到所有 C++ 类型；这里先掌握本例中对象关系的变化。

## 方案：先分清对象、副本、别名和地址

关键代码来自完整的 [demos/00.cpp](../demos/00.cpp)：

```cpp
Note original{"original"};        // 一个 Note 对象
Note copied = original;          // 新建独立 Note
Note& alias = original;          // original 的别名
Note* observer = &original;      // 保存 original 的地址，只借用
```

用一张表判断四个名字：

| 名字 | 是否新建 Note | 是否拥有 Note | 能否为空 | 修改 `text` 会影响谁 |
| --- | --- | --- | --- | --- |
| `original` | 是 | 是 | 否 | original |
| `copied` | 是 | 是 | 否 | copied |
| `alias` | 否 | 否，只借用 | 否 | original |
| `observer` | 否 | 否，只借用 | 是，可为 `nullptr` | 指向的对象 |

本例修改 copied 不影响 original，因为两个 Note 各自拥有 string。通过 alias 或 observer 修改，则是在修改 original。

对象关系可以画成：

```text
original ──拥有──► string "original"
   ▲
   ├── alias：同一个 Note 的别名
   └── observer：保存这个 Note 的地址

copied ───拥有──► 另一份 string
```

## 读变量时固定问四个问题

1. 完整类型是什么？
2. 这个变量拥有一个值，还是借用别的对象？
3. 代码是在复制、借用，还是转移所有权？
4. 若它是借用，谁保证目标仍然活着？

后续遇到 `T`、`T&`、`T*`、`unique_ptr<T>` 时，都可以用这四问拆解。

## 生命周期：借用不能比目标活得久

`alias` 和 `observer` 都不会让 original 延长生命：

```text
进入作用域
  创建 original
  alias 和 observer 借用 original
  可以通过借用访问 original
离开作用域
  original 析构
  旧引用和旧地址不能再使用
```

引用必须初始化，不能用 `nullptr` 表示“没有对象”；指针可以为空，也可以改指向。两者都可能因为目标先销毁而悬空。

C++ 不等于所有对象都要手动 delete。现代 C++ 通常优先使用局部对象和标准容器；需要动态生命周期时使用智能指针；原始指针常用于借用或对接 C 接口。

## Java 对照

| 想表达的关系 | C++ 常见写法 | Java 中较接近的理解 |
| --- | --- | --- |
| 当前作用域直接拥有对象 | `Note note;` | Java 局部变量通常只保存引用；对象本体由 GC 管理 |
| 创建独立副本 | `Note copy = note;` | 常需显式复制构造或 copy 方法 |
| 必须存在的借用 | `Note& ref` | 没有完全对应语法，可理解为不可为 null 的临时别名 |
| 可以为空的借用 | `Note* ptr` | 可为 null 的引用，但不会延长对象生命 |
| 独占动态对象 | `std::unique_ptr<Note>` | Java 没有直接对应物；所有权被写进 C++ 类型 |

## 验证：修改落到哪个对象

在 `C++快速入门` 目录执行：

```bash
mkdir -p build
c++ -std=c++17 -Wall -Wextra -Wpedantic -g demos/00.cpp -o build/demo_00
./build/demo_00
```

预期输出：

```text
original: changed through reference
copy: changed copy
```

完整 demo 中，`rename(alias)` 通过别名修改 original；`copied.text` 修改另一份 Note，所以两行输出不同。函数参数中的引用会在第 03 篇展开。

## 常见坑

- 看到 `T b = a` 就按 Java 引用赋值理解；对本例 Note，它创建的是新对象。
- 把引用或指针当成所有者；借用存在不代表目标一定仍然存活。
- 认为指针非空就安全；非空地址也可能已经悬空。
- 看到 `std::move` 就认定一定发生了资源转移；真正行为由类型的移动操作决定，第 09 篇会继续说明。
- 为了“像 Java 对象”而默认使用 shared_ptr；所有权应按真实生命周期选择。

## 三级练习

1. **预测**：删除 `rename(alias)` 后，两行输出分别是什么？
2. **修改**：把 `copied.text = ...` 改为 `alias.text = ...`，先画关系图，再预测 original 和 copied。
3. **独立完成**：创建第二个 Note，让 observer 改指向它；说明 observer 改指向为什么不会改变 alias 绑定的对象。

## 完成标准

不看答案也能说清 original、copied、alias、observer 是否创建对象、是否拥有对象、能否为空，以及谁的生命周期决定借用是否有效。
