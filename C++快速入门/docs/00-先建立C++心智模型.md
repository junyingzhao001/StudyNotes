## 本篇目标

先分清 C++ 中最容易混在一起的四件事：对象、对象的副本、对象的别名、对象的地址。知道后续每篇到底在解决什么问题。

## 学习作用

有 Java 基础的人通常不是看不懂 if 或 for，而是会自然地把“变量里装着对象引用、对象交给 GC”这套模型带到 C++。这会让 `&`、`*`、拷贝、析构和智能指针显得互相矛盾。先把模型换过来，后面的语法会顺很多。

## 先记住四个问题

读到一个 C++ 变量时，依次问：

1. 它的完整类型是什么？
2. 它自己拥有一个值，还是引用/指向别的对象？
3. 谁负责保证目标对象仍然活着？
4. 这段代码是在复制、借用，还是转移所有权？

下面四行看起来接近，含义完全不同：

```cpp
Note original{"hello"};       // 创建 Note 对象
Note copied = original;       // 创建独立副本
Note& alias = original;       // alias 是 original 的别名
Note* pointer = &original;    // pointer 保存 original 的地址
```

修改 copied 通常不影响 original；通过 alias 或 pointer 修改，则是在改 original。`pointer` 可以是 nullptr；引用 alias 必须初始化，而且每次使用时被引用对象都必须仍然存活。引用也可能因为目标已经销毁而悬空。

## 和 Java 的第一组对照

假设 Note 是普通类：

```java
Note original = new Note("hello");
Note another = original;
```

Java 的 another 和 original 通常指向同一个对象。C++ 的 `Note another = original;` 通常直接复制出另一个 Note。想表达别名，需要显式写 `Note&` 或指针；想表达动态对象的所有者，通常用 `std::unique_ptr<Note>`。

| 想表达的意思 | C++ 常见写法 | Java 中较接近的理解 |
| --- | --- | --- |
| 当前作用域拥有一个对象 | `Note note;` | 局部变量引用一个由 GC 管理的对象，但销毁规则不同 |
| 创建独立副本 | `Note copy = note;` | 常要显式 clone/复制构造，普通赋值不是这个意思 |
| 必须存在的借用 | `Note& ref` | 没有完全对应的语法，可理解为不能为 null 的临时别名 |
| 可以为空的借用 | `Note* ptr` | 可为 null 的引用，但 C++ 不会帮它延长对象生命 |
| 独占动态对象 | `std::unique_ptr<Note>` | Java 没有直接对应物；它把“唯一所有者”写进类型 |

## 生命周期先看作用域

```text
进入大括号
  创建局部对象 original
  引用和指针可以暂时借用它
离开大括号
  original 自动析构
  之前指向它的引用或指针不能再使用
```

C++ 不等于“所有东西都要手动 delete”。现代 C++ 的默认顺序是：优先局部对象和标准容器；确实需要动态生命周期时用智能指针；原始指针多用于借用或对接 C 接口。

## 可运行 demo

源码：[demos/00.cpp](../demos/00.cpp)。从 `C++快速入门` 目录执行：

```bash
mkdir -p build
c++ -std=c++17 -Wall -Wextra -Wpedantic -g demos/00.cpp -o build/demo_00
./build/demo_00
```

```cpp
#include <iostream>
#include <string>

struct Note {
    std::string text;
};

void rename(Note& note) { note.text = "changed through reference"; }

int main() {
    Note original{"original"};
    Note copied = original;  // 复制出独立对象
    Note& alias = original;  // original 的别名
    Note* observer = &original; // 保存地址，只借用

    copied.text = "changed copy";
    rename(alias);

    std::cout << "original: " << observer->text << '\n';
    std::cout << "copy: " << copied.text << '\n';
}
```

预期输出：

```text
original: changed through reference
copy: changed copy
```

## 按行理解

original 与 copied 是两个 Note 对象，各自拥有 string。alias 没有创建第三个 Note，它只是 original 的另一个名字。observer 也不拥有 Note，只保存 original 的地址。rename 通过引用修改 original，所以 observer 随后看到新文本；copied 保持自己的文本。

## 动手练习与完成标准

先预测删除 `rename(alias)` 后的输出，再运行验证。随后把 `copied.text` 改为 `alias.text`，解释为什么 original 会变化。

当你能不看答案说清 original、copied、alias、observer 分别是什么，以及谁的生命周期决定 observer 是否有效，就可以进入第 01 篇。
