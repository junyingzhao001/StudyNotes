# 13 · 语法与读码速查

[返回学习地图](../README.md) · [下一篇：C接口数组与字符串视图](14-C接口数组与字符串视图.md)

## 先说结论

这是一张读码地图，不要求从头背到尾。遇到陌生声明时，先确认具体类型，再判断拿到的是对象、副本、借用还是拥有者，最后检查生命周期和错误边界。

读完后，你能把常见符号翻译成普通语言，并把问题归入编译、链接、运行、生命周期或并发类别。这样查错更快，也能避免只盯着一段复杂语法猜意思。

## 问题：陌生符号容易遮住真正的数据关系

C++ 能在一个声明里同时表达类型、const、引用、模板和作用域。逐个背符号仍可能看不懂程序，因为真正要追的是谁拥有对象、谁只是在借用、对象何时失效，以及错误和线程由谁处理。

## 方案：先按这条顺序读代码

```text
类型是什么
   ↓
值 / 引用 / 指针 / 智能指针分别由谁拥有
   ↓
对象何时销毁，容器修改会不会让借用失效
   ↓
错误怎样返回，共享状态怎样同步
```

## 高频类型与符号

| 写法 | 先翻译成什么 |
| --- | --- |
| `T value` | 一个 T 对象；内置类型要留意是否初始化 |
| `T& value` | 已有 T 对象的引用别名，不能表示空 |
| `const T& value` | 只读借用，不转移所有权 |
| `T* value` | 指向 T 的指针，可能为空，也可能悬空 |
| `const T* value` | 通过该指针不能修改目标 |
| `T* const value` | 指针自身不能改指向，目标仍可能可改 |
| `&value` | 表达式中取得地址 |
| `*pointer` | 解引用；前提是指针非空且目标仍有效 |
| `object.member` / `pointer->member` | 访问对象成员 / 指针目标成员 |
| `std::vector<T>` | 按值拥有一组 T 的标准库容器 |
| `std::unique_ptr<T>` | 独占拥有动态 T 对象 |
| `std::shared_ptr<T>` | 多个拥有者共享 T 的生命期；不代表 T 线程安全 |
| `std::optional<T>` | 可能有一个 T，也可能为空 |
| `auto value` | 推导一个普通变量，通常不保留引用 |
| `auto& value` | 推导引用，绑定到原对象 |
| `Class::method` | Class 作用域中的名字 |
| `using TaskId = int` | 类型别名；TaskId 与 int 仍是同一类型 |
| `std::move(value)` | 允许后续操作选择移动，本身不搬资源 |

## 函数、Lambda 与类型机制

| 写法 | 含义 |
| --- | --- |
| `void print(const T& value)` | 只读借用 T，不返回值 |
| `[](int x) { return x > 0; }` | 不捕获外部变量的 Lambda |
| `[limit](int x) { ... }` | 复制捕获 limit |
| `[&limit](int x) { ... }` | 引用捕获 limit，必须保证其生命期 |
| `template<typename T>` | 用类型参数生成/选择编译期代码 |
| `virtual` / `override` | 开启运行时虚分派 / 检查是否正确覆盖 |
| `= default` | 请求编译器生成默认实现 |
| `= delete` | 禁止这个函数，例如禁止复制 |
| `constexpr` | 值或函数可在满足条件时参与编译期计算 |

C++ 支持函数重载：同一作用域可以有多个同名函数，只要参数列表可区分。定位调用时要核对完整实参类型，不能只按函数名搜索一个实现。

默认参数通常写在头文件声明处，并在同一可见作用域只指定一次。例如 `void log(std::string_view text, int level = 1);`。调用 `log("ready")` 时由编译器补上参数，它不是运行时重载。

## 作用域速查

作用域回答“名字在哪里可见”，生命周期回答“对象在运行时活到什么时候”。两者相关，但不是同一件事。完整讲解和可运行示例见 [01A · 作用域、头文件、cpp 与宏定义](01A-作用域头文件与宏定义.md)。

| 作用域 | 常见用途 | 容易混淆的点 |
| --- | --- | --- |
| `{ ... }` 块作用域 | 限制临时变量和 RAII 资源范围 | 内层同名变量会遮蔽外层变量 |
| 函数作用域 | 参数与局部变量服务一次调用 | 返回引用/指针时目标可能已销毁 |
| 类作用域 | 组织成员状态与行为 | 尾部 `const` 限制通过 this 修改成员 |
| 命名 namespace | 组织公开名字、减少冲突 | 不决定目录，也不是访问控制 |
| 匿名 namespace | 让名字只在当前 cpp 使用 | 常用于实现辅助函数，不放公开 API |

## 声明、定义与头文件速查

| 概念 | 作用 | 常见错误 |
| --- | --- | --- |
| 声明 `int normalize(int);` | 告诉编译器名字和类型 | 看得见声明，但链接时找不到定义 |
| 定义 `int normalize(int x) { ... }` | 提供函数实现 | 普通外部函数定义多份导致重复符号 |
| `#include "score.h"` | 让当前编译单元看到头文件文本 | 把 include 误当成链接实现 |
| include guard | 防止头文件在同一编译单元重复展开 | 宏名冲突或漏写结尾 `#endif` |
| `.cpp` | 独立编译为目标文件 | 漏放进编译命令或 CMake target |

入门时先记：普通非 inline 函数通常在整个程序中定义一次，声明可以被多个 cpp 看见；模板和 inline 定义常放头文件，但每处看到的定义必须一致。

## 条件编译与宏替代方案

宏由预处理器在正式编译前处理，不理解类型、namespace 或函数求值。合理用途主要是头文件保护和构建条件：

| 需求 | 可用写法 | 更适合普通业务逻辑的方案 |
| --- | --- | --- |
| 防止头文件重复包含 | `#ifndef` / `#define` / `#endif` | `#pragma once` 也常见且获主流编译器支持，但未进入 C++ 标准 |
| 构建时开启跟踪代码 | `#ifdef QUICKSTART_TRACE` | 若是运行时开关，使用有类型的配置值 |
| 定义常量 | 不推荐 `#define MAX 100` | `inline constexpr int kMax{100};` |
| 封装计算 | 不推荐函数式宏 | 普通函数、`inline` 函数或函数模板 |
| 表示有限选项 | 不推荐整数宏 | `enum class` |
| 给类型取可读名字 | 不推荐宏替换类型 | `using` |

函数式宏可能重复求值，也不受作用域和类型检查保护。构建宏应由构建目标统一定义，避免不同 cpp 看到互相矛盾的类布局或声明。真实示例见 [structure_demo](../structure_demo) 与 [第 15 篇](15-CMake工程化构建与测试.md)。

## 并发符号速查

| 写法 | 含义 |
| --- | --- |
| `std::thread worker(task)` | 创建后即可并发执行；关联线程析构前必须 join/detach |
| `std::lock_guard<std::mutex> lock(m)` | 当前作用域持有 m，离开时自动解锁 |
| `cv.wait(lock, predicate)` | 等待时解锁，醒来后重新加锁并检查谓词 |
| `std::future<T>` | 稍后取得一个结果或异常，取值动作只能进行一次 |
| `std::atomic<int>` | 对单个整数执行原子读写/读改写，不保护复合状态 |

## 把复杂声明拆成一句话

贯穿课程的声明是：

```cpp
const std::vector<Task>& TaskStore::tasks() const;
```

从函数名向外读：这是 TaskStore 的 `tasks` 方法；不接收参数；尾部 `const` 表示不能通过该调用修改普通成员；返回 `vector<Task>` 的 const 引用。它不复制容器，也不转移所有权，因此使用期间 TaskStore 必须仍然存活。

遇到 `std::unique_ptr<Shape> shape = std::make_unique<Rectangle>(...)` 时同样分层：右侧创建并独占 Rectangle；左侧用 Shape 接口持有；虚调用进入 Rectangle 实现；通过基类指针销毁需要虚析构。

## 读一段 C++ 时问七个问题

1. 输入、输出和错误分别怎样表达？
2. 每个变量的具体类型是什么，`auto` 推导出什么？
3. 拿到的是副本、引用、借用指针还是拥有者？
4. 对象何时销毁，借用会不会悬空？
5. 容器操作会不会使迭代器、指针或引用失效？
6. 修改状态发生在哪里，`const` 约束是否匹配？
7. 若有多线程，共享哪些对象，每次访问遵守哪套同步规则？

## 报错快速归类

| 现象 | 第一检查点 |
| --- | --- |
| 找不到类型或名字 | 是否 include 正确头文件、作用域是否正确、是否写 `std::` |
| C++17 语法不支持 | 编译命令是否有 `-std=c++17` |
| undefined symbol/reference | 提供定义的 cpp 或库是否进入链接 target |
| duplicate symbol/multiple definition | 是否把普通定义放进公共头文件或重复编译源文件 |
| use of deleted function | 是否复制 unique_ptr，或类型明确删除该操作 |
| 模板错误很长 | 从首个错误和自己代码行开始，核对实际类型 |
| 崩溃或偶发错误 | 空指针、越界、悬空、未初始化、迭代器失效 |
| 相对路径找不到文件 | 确认运行时工作目录，而不是源码目录 |
| thread 析构时 terminate | 是否仍有 joinable 线程 |
| 多线程偶发错值 | 是否无锁读写共享数据或对象提前销毁 |
| worker 无法退出 | 谓词、停止状态、通知与 join 是否形成完整协议 |

## 容易翻车的地方

- 速查表只能帮助定位概念，不能替代接口合同和对象生命周期分析。
- 两段语法看起来相似，不代表所有权相同；值、引用、原始指针和智能指针承担的责任不同。
- 代码通过编译不代表借用仍有效，也不代表并发协议正确；继续检查拥有者、失效条件和同步规则。
- 模板报错很长时不要从最后一行倒猜，先找第一条指向自己源码的诊断并核对实际类型。
