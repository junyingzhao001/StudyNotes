## 目标与作用

遇到陌生声明时快速拆解语法，并把编译错误或运行问题归到正确类别。本篇是辅助查询页，无独立 demo；代码练习分别见第 03、06、08、10、12 篇。

## 高频符号

| 写法 | 含义 |
| --- | --- |
| `T value` | 一个 T 对象，注意是否已初始化 |
| `T& value` | 对已有对象的引用 |
| `const T& value` | 只读借用 |
| `T* value` | 指向 T 的指针，可能为空 |
| `const T* value` | 通过指针只能读取目标 |
| `T* const value` | 指针不能改指向 |
| `&value` | 表达式中取地址 |
| `*pointer` | 解引用，前提是目标有效 |
| `object.member` / `pointer->member` | 访问对象 / 指针目标的成员 |
| `std::vector<T>` | 标准库模板类型 |
| `Class::method` | 类作用域中的成员 |
| `auto` / `auto&` | 推导普通变量类型 / 引用类型 |
| `[](int x) { return x > 0; }` | 不捕获外部变量的 Lambda |
| `std::move(value)` | 允许选择移动操作的转换，本身不转移资源 |
| `virtual` / `override` | 虚函数 / 检查覆盖基类虚函数 |
| `= default` / `= delete` | 使用编译器生成实现 / 禁止某个函数 |
| `using TaskId = int` | 给类型取别名，不创建新的独立类型 |
| `namespace app { ... }` | 把名字放入作用域，减少冲突 |
| `constexpr` | 值或函数可参与满足条件的编译期计算 |
| `std::thread worker(task)` | 创建后即可并发执行，析构前必须 join/detach |
| `std::lock_guard<std::mutex> lock(m)` | 当前作用域持有 m，离开作用域自动解锁 |
| `cv.wait(lock, predicate)` | 解锁并等待，醒来重新加锁并检查谓词 |
| `std::future<T>` | 稍后取得一个结果或异常，普通 future 的 get 只成功一次 |
| `std::atomic<int>` | 对单个整数执行原子读写或读改写 |

## 常见声明补充

C++ 允许函数重载：同一作用域中多个函数同名，只要参数列表可区分。编译器根据实参类型选择候选，因此看到同名调用时要核对完整参数，不能只按函数名搜索一个实现。

```cpp
void print(int value);
void print(const std::string& value);
```

默认参数通常写在头文件的声明处，并且在同一可见作用域只指定一次：`void log(std::string_view text, int level = 1);`。调用 `log("ready")` 时编译器补上 1，它不是运行时的重载查找。

`using TaskId = int` 只是提高可读性的别名，TaskId 和 int 仍是同一种类型；如果业务必须阻止混用，需要设计包装类型。constexpr 变量本身是 const；constexpr 函数在常量上下文可于编译期求值，也可以在普通上下文于运行期执行。

## 声明拆解练习

```cpp
const std::vector<Task>& TaskStore::tasks() const;
```

从函数名开始读：TaskStore 的 tasks 方法，不接收参数；尾部 const 限制通过 this 修改普通成员；返回的是 vector<Task> 的 const 引用。它不复制整个容器，不把所有权交给调用者，并要求 store 在使用期间仍存活。

```cpp
std::unique_ptr<Shape> shape = std::make_unique<Rectangle>(3.0, 4.0);
```

右侧创建 Rectangle，由 unique_ptr 独占管理；左侧以 Shape 接口持有它。调用虚函数会进入 Rectangle 实现；通过该基类指针销毁对象需要正确的虚析构设计。

## 读一段 C++ 的六个问题

1. 输入是什么，函数返回什么，错误如何表示？
2. 每个变量的具体类型是什么，auto 推导出了什么？
3. 这里拿到的是副本、引用、借用指针还是拥有者？
4. 对象什么时候销毁，借用是否可能悬空？
5. 容器操作会不会使已有迭代器、指针或引用失效？
6. 修改状态发生在哪里，是否需要 const 约束？
7. 如果有多条线程，共享的是哪些对象，每次访问遵守哪套同步规则？

## 报错排查

| 现象 | 优先检查 |
| --- | --- |
| 找不到标准库类型 | 是否 include 正确头文件、是否写 std:: |
| C++17 语法不支持 | 是否传入 -std=c++17 |
| undefined symbol / reference | 是否把实现 cpp 一起参与链接 |
| duplicate symbol | 是否在多个编译单元重复定义普通函数 |
| use of deleted function | 是否复制了 unique_ptr，或类型明确禁止此操作 |
| 模板报错很长 | 从首个错误和自己代码对应行看起，核对实际类型 |
| 崩溃或偶发错误 | 空指针、越界、悬空、未初始化、迭代器失效 |
| 相对路径找不到文件 | 先确认运行时工作目录，而非源码目录 |
| thread 析构时 terminate | 是否还有 joinable 线程没有 join/detach |
| 多线程偶发错值 | 是否存在无锁共享写、无锁读取或对象提前销毁 |
| worker 无法退出 | 条件变量谓词、停止状态、通知和 join 是否形成完整协议 |

本机可以使用地址与未定义行为检查器执行课程验证：

```bash
SANITIZE=1 bash scripts/run_all.sh
```

这些工具能帮助发现部分运行错误，但跑过的路径无错误不代表程序绝对安全。ASan/UBSan 不检测普通数据竞争；第 18 篇另有可选的 ThreadSanitizer lab。单步调试可以编译时加 -g，然后用 `lldb ./build/task_cli`，依次输入 `breakpoint set --name main`、`run`、`next`、`frame variable`；退出调试器用 `quit`。
