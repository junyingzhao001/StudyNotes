# 01 · 编译运行与程序结构

[返回学习地图](../README.md) · [下一篇：类型初始化与常用语法](02-类型初始化与常用语法.md)

## 本篇目标

能够独立编译运行程序，区分源码、编译、链接和运行。

## 学习作用

遇到构建报错时，知道问题发生在哪一步；理解 C++ 为什么通常需要先构建。

## 核心知识

C++ 常见流程是：`.cpp` 源码 → 预处理（展开 include 等）→ 编译 → 目标文件 → 链接 → 可执行文件。一个简单编译命令会替你完成这些阶段。

`#include <iostream>` 引入标准输入输出声明；`main` 是程序入口，返回 0 通常表示成功；`std::` 表示名字来自标准库命名空间。`<<` 在输出流中表示写入，并不是这里在做位移运算。`'\n'` 表示换行。

和 Java/Kotlin 的常见使用方式不同，这里的程序直接生成本机可执行文件，不依赖 JVM。C++ 的变量也有类型，语句通常以分号结束。已有语言基础的话，循环和条件判断可边用边熟悉。

## Java 对照：javac、java 与 c++

Java 常见流程是 `.java → javac → .class → JVM 执行`。C++ 常见流程是 `.cpp → 编译为目标文件 → 链接 → 本机可执行文件`。一个 `c++ source.cpp -o app` 命令把编译和链接连续完成。

Java 的 import 让类型名可见，但类的字节码仍要在 classpath；C++ 的 `#include` 让声明可见，但实现仍要由目标文件或库参与链接。以后看到“头文件明明 include 了，为什么还 undefined symbol”，就是声明已看到、实现却没链接进来。

## 可运行 demo

源码：[demos/01.cpp](../demos/01.cpp)。从 `C++快速入门` 目录执行：

```bash
mkdir -p build
c++ -std=c++17 -Wall -Wextra -Wpedantic -g demos/01.cpp -o build/demo_01
./build/demo_01
```

```cpp
#include <iostream>

int main() {
    const int days = 7; // 初始化后不再修改
    std::cout << "Hello, C++17!" << '\n';
    std::cout << "Plan: " << days << " days" << '\n';
    return 0;
}
```

预期输出：

```text
Hello, C++17!
Plan: 7 days
```

## 按行理解

程序从 main 开始，先创建只读整数 days，再把三段内容依次写入 `std::cout`。第二个输出表达式从左向右把字符串、整数和换行写进同一个输出流。离开 main 时局部变量销毁，返回 0 表示正常结束。

## 常见坑

头文件提供声明，通常不等于把某个库的全部实现链接进程序。找不到标识符多发生在编译阶段；undefined symbol / undefined reference 常见于链接阶段。

## 动手练习

1. 预测：把 days 改成 10 后，哪一行输出变化？
2. 修改：新增一行输出自己的学习目标。
3. 独立：故意删掉一个分号观察编译错误；再声明但不定义一个函数并调用，观察链接错误。恢复后运行验证。

## 完成标准

能用一条命令生成并执行程序；能指出 main、include 和 std 各自的角色。
