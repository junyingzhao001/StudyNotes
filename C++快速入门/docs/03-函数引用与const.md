# 03 · 函数、引用与 const

[返回学习地图](../README.md) · [上一篇：类型、初始化与常用语法](02-类型初始化与常用语法.md) · [下一篇：指针、生命周期与内存](04-指针生命周期与内存.md)

## 先说结论

C++ 函数签名会直接告诉你参数是独立值、只读借用，还是可修改借用。读懂 `T`、`const T&` 和 `T&`，就能在调用函数前预测“会不会复制、会不会改到调用者、借用需要活多久”。

读完本篇，你能根据参数类型为函数选择传值或传引用，能解释 count 为什么有时改变、有时不变，也能避免返回局部对象引用。实际项目的接口、容器遍历和回调代码会反复使用这些规则。

## 问题：函数接收“对象”到底接收了什么

Java 的参数始终按值传递：

- 传入 int，方法得到整数副本；
- 传入对象变量，方法复制的是引用值，所以可以修改对象内容；
- 给形参重新赋一个对象，不会让调用者变量改指向。

C++ 还可以在参数类型中显式声明引用。调用处看起来都像 `function(value)`，实际语义由函数签名决定。

## 方案：先从三个函数签名判断意图

关键代码来自完整的 [demos/03.cpp](../demos/03.cpp)：

```cpp
int addCopy(int value) { return ++value; }
void addReference(int& value) { ++value; }
std::size_t length(const std::string& text) { return text.size(); }

int count{10};
const int copiedResult = addCopy(count);
addReference(count);
```

| 参数形式 | 函数得到什么 | 能否修改调用者对象 | 适合场景 |
| --- | --- | --- | --- |
| `T value` | 一个局部参数对象 | 修改参数本身不会改原对象 | int、bool 等小值，或函数需要自己的值 |
| `const T& value` | 原对象的只读别名 | 不能通过此引用修改 | 只读使用 string、vector 等对象 |
| `T& value` | 原对象的可修改别名 | 可以 | 函数职责就是原地修改调用者对象 |

本例把命名的 count 传给 `int value`，局部参数从 count 的值初始化，因此 `++value` 不改变 count。对一般类类型，传值参数可能从实参复制或移动；第 09 篇会继续讲移动。现在先记住：函数拥有自己的参数对象。

`addReference` 的 value 是 count 的别名，`++value` 就是在增加 count。

`length` 只读借用 greeting，不复制整段 string。`const` 保证函数不能通过 text 修改它，但不保证世界上没有其他代码修改同一对象。

## 用变量变化验证签名

| 时刻 | count | copiedResult | 原因 |
| --- | ---: | ---: | --- |
| 初始化后 | 10 | 尚未创建 | count 自己拥有值 |
| `addCopy(count)` 后 | 10 | 11 | 函数增加参数副本，并返回结果 |
| `addReference(count)` 后 | 11 | 11 | 引用参数是 count 的别名 |

引用不是一个可重新绑定的 Java 对象变量。`int& ref = first;` 建立别名后，后续 `ref = second;` 的含义是把 second 的值赋给 first，不是让 ref 改为绑定 second。

## 参数选择从意图出发

可以把下面规则当作起点：

- int、bool、枚举等小类型通常按值传递；
- 只读使用 string、vector 等对象，常用 `const T&`；
- 明确要原地修改调用者对象时，用 `T&`；
- 允许“没有对象”时，用第 04 篇的指针，或后续出现的 optional；
- 需要函数保留一份数据供以后使用时，应复制或转移到自己的对象中，不能盲目保存短期借用。

返回结果时，普通值通常是清晰的默认选择。现代 C++ 会使用移动或返回值优化减少不必要成本，不要为了“避免复制”而返回局部变量引用。

## 生命周期：引用只是借用

引用必须在创建时绑定对象，而且目标必须在每次使用引用时仍然存活。函数不能返回局部变量的引用，因为函数结束后该局部对象已经销毁。

`const T&` 参数可以临时绑定到一个临时值，该临时值会活到这次完整调用表达式结束。被调用函数仍不能把这条引用保存起来供以后使用。入门时优先传命名对象，并持续使用“借用不能比目标活得久”这条检查规则。

## Java/Kotlin 对照

| C++ 参数 | 调用含义 | Java/Kotlin 中较接近的理解 |
| --- | --- | --- |
| `Task task` | 函数拥有局部参数对象 | 先得到独立 Task 值再处理 |
| `const Task& task` | 只读借用原 Task | 传对象引用并约定只读，但 C++ 由类型检查 |
| `Task& task` | 可修改借用原 Task | 方法修改传入对象内容，但 C++ 是显式别名 |
| `Task* task` | 可空借用 | 可为 null 的对象引用，但没有 GC 自动保活 |

不要说“Java 是引用传递”。准确表述是：Java 复制参数值，而对象变量的值是一条引用；C++ 可以用 `T&` 在类型中明确声明引用参数。

## 验证：运行并对照状态表

在 `C++快速入门` 目录执行：

```bash

./build/demo_03
```

预期输出：

```text
after copy: 10
returned copy: 11
after reference: 11
length: 5
```

前两行证明值参数与原 count 独立；第三行证明引用参数修改原对象；最后一行证明 length 能只读访问 greeting。

## 常见坑

- 只看调用写法，不看函数声明，因而误判是否会修改原对象。
- 把 `const T&` 理解成对象在任何地方都不会变化；它只限制通过这条引用进行修改。
- 返回局部变量的引用或指针，导致函数结束后借用悬空。
- 为了避免所有复制而到处使用引用，却没有写清生命周期。
- 忘记普通 `auto` 常会得到副本；`const auto&` 才明确保留只读引用。
- 认为引用赋值会改绑到另一个对象。
