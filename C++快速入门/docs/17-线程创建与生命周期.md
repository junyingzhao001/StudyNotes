# 17 · 线程创建与生命周期

[返回学习地图](../README.md) · [下一篇：数据竞争与互斥锁](18-数据竞争与互斥锁.md)

## 本篇目标

会创建 `std::thread`、传递参数并正确 join，理解线程对象与实际执行线程的生命周期，以及为什么不能随意 detach。

## 学习作用

实际项目经常需要把耗时计算、后台 I/O 或任务消费移出主线程。线程代码首先要解决的不是“跑得更快”，而是每条线程如何结束、数据活多久、错误在哪里处理。

## Java 对照

| Java | C++17 | 关键差别 |
| --- | --- | --- |
| `new Thread(task).start()` | 构造 `std::thread(task)` | C++ thread 构造后也可能立即开始运行 |
| `thread.join()` | `thread.join()` | 都等待目标线程结束 |
| JVM 管理对象生命 | thread 拥有任务对象及按值保存的参数 | `std::ref`、引用捕获、裸指针和 `this` 所借用的目标不会因此延长生命 |
| ExecutorService | 后面的 TaskExecutor 项目 | 业务代码通常更适合提交任务而非到处创建裸线程 |
| 未捕获异常在线程中结束该线程 | 异常逃出 C++ 线程入口会调用 `std::terminate` | join 不会自动把普通 thread 的异常带回主线程 |

## 创建后已经并发

```cpp
std::thread worker(function, argument1, argument2);
```

构造返回前后，worker 都可能已经开始执行，所以不能依赖“下一行代码一定先运行”。传给 thread 的参数默认被复制或移动到线程内部。若函数参数需要引用，调用处要显式使用 `std::ref`，并保证目标对象活到线程结束。

```cpp
int result{0};
std::thread worker(calculate, 21, std::ref(result));
worker.join();
std::cout << result; // join 后再读
```

join 不只是等待。它还建立线程间同步：worker 在结束前对 result 的写入，在 join 返回后可被主线程安全观察。本例主线程在 join 前不读 result，因此不存在并发读写。

## thread 对象必须收尾

`joinable()` 表示 thread 对象仍关联一条需要处理的执行线程。线程函数即使已经自然运行完，只要还没 join/detach，thread 对象仍可能是 joinable。

joinable 的 `std::thread` 析构会调用 `std::terminate`，不会自动 join。每条线程必须在所有控制路径上恰好 join 或 detach。C++17 工程常用自定义 RAII 包装保证 join；C++20 提供更方便的 `std::jthread`，但本课程保持 C++17。

detach 让 thread 对象不再管理执行线程，主线程也无法再 join。它不等于可靠的后台任务管理：进程可能先退出，捕获的局部引用或 this 可能已经悬空，异常仍可能终止程序。入门和大多数业务代码优先 join 或使用受管理的执行器。

Java 的 daemon thread 和 Thread.interrupt 在 C++17 都没有直接对应物。协作停止通常使用受 mutex 保护的停止状态或 atomic 标志；若线程正等待 condition_variable，还必须更新状态并通知。第 19、22 篇会展示完整停止协议。

## 可运行 demo

源码：[demos/17.cpp](../demos/17.cpp)：

```bash
mkdir -p build
c++ -std=c++17 -Wall -Wextra -Wpedantic -g -pthread \
  demos/17.cpp -o build/demo_17
./build/demo_17
```

```cpp
#include <functional>
#include <iostream>
#include <thread>

void calculate(int input, int& output) {
    output = input * 2;
}

int main() {
    int result{0};
    std::thread worker(calculate, 21, std::ref(result));
    worker.join();

    std::cout << "result: " << result << '\n';
    std::cout << std::boolalpha
              << "joinable after join: " << worker.joinable() << '\n';
}
```

预期输出：

```text
result: 42
joinable after join: false
```

## 时间线

```text
主线程：创建 worker ───────── join 等待 ─────────► 读取 result=42
工作线程：          calculate 写 result ─► 结束
```

result 和 worker 都是 main 的局部对象。worker 完成写入后，join 返回；main 最后析构一个已经不再 joinable 的 thread 对象。

## 常见坑

- 不要用 sleep 猜线程是否执行完；sleep 不是同步协议。
- 不要让工作线程直接输出并把行顺序当测试结果，调度顺序没有保证。
- `std::ref` 只传递借用，不延长 result 生命周期。
- 普通 thread 的入口函数若可能抛异常，应在线程内部 catch，或使用第 20 篇的 future 传回异常。
- 循环创建多条 thread 时，中途构造失败也要保证之前创建的线程被 join；实际项目应使用 RAII 管理器。
- shared_ptr 的引用计数可以由多线程安全增减，不代表它所指对象的字段自动线程安全。

## 三级练习与完成标准

1. 预测：把 join 移到输出之后为什么不安全？不要运行有数据竞争的版本。
2. 修改：让 worker 接收两个整数并把和写入 result。
3. 独立：启动三条线程分别计算一个独立数组槽位，全部 join 后由 main 按固定顺序输出。

完成标准：能解释参数为何需要 std::ref、join 前后有哪些生命周期和同步保证，并能保证每个 joinable thread 在析构前正确收尾。
