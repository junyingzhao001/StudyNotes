# 09 · 拷贝移动与返回值

[返回学习地图](../README.md) · [下一篇：模板与运行时多态](10-模板与运行时多态.md)

## 先说结论

这一篇解决“赋值之后两个变量到底是不是同一个对象”的问题。读完后，你能区分副本、引用别名和资源转移，能安全使用 `std::move`，也知道函数返回新对象时应直接按值返回。

这直接影响所有权、正确性和成本。把 C++ 的 `auto b = a` 当成 Java 的引用赋值，会让你误判修改范围；把所有值都 `std::move`，又可能留下难以使用的源对象并妨碍返回值优化。

## 问题：同一个等号可能表达不同语义

贯穿本篇的例子是一组姓名：`original` 保存 `Ada, Bjarne`，随后需要一份可独立修改的副本，最后把原容器的资源交给另一个变量。

Java 中的 `List<String> copied = original;` 通常只是复制引用，两个变量指向同一个 List。C++ 中要先看完整类型：

| C++ 写法 | 含义 | 修改新变量是否影响原变量 |
| --- | --- | --- |
| `auto copied = original` | 按类型规则创建副本 | 对 `vector<string>` 不影响 |
| `auto& alias = original` | 创建引用别名 | 会影响同一个对象 |
| `auto moved = std::move(original)` | 允许目标选择移动构造 | 资源通常转移，源仍有效但状态未指定 |

“拷贝”也不必然等于所有深层对象都独立。复制 `vector<int>` 会得到独立整数；复制 `vector<shared_ptr<User>>` 时，容器独立，但其中的 shared_ptr 仍共享 User。`unique_ptr` 则禁止复制。

## 方案：先决定语义，再选择写法

[完整 demo](../demos/09.cpp) 的关键路径是：

```cpp
auto original = makeNames();
auto copied = original;
copied.at(0) = "Grace";

auto moved = std::move(original);
original = {"New value"}; // 重新赋值后再读取
```

第一步需要两个独立列表，所以使用拷贝。第二步不再需要 original 原有内容，所以允许 moved 接管其资源。最后先给 original 一个新值，再读取它，避免依赖移动后的未指定内容。

`std::move` 这个名字容易误导：它本身不搬数据，只把表达式转换成“允许被移动”的形式。真正是否移动，由目标类型的构造或赋值操作决定。对 `const` 对象调用 `std::move` 常常仍会拷贝，因为移动通常需要修改源对象。

## 返回局部对象：直接 return

`makeNames` 创建一个新 vector 时，推荐这样写：

```cpp
std::vector<std::string> makeNames() {
    std::vector<std::string> result{"Ada", "Bjarne"};
    return result;
}
```

编译器可以使用返回值优化；不满足消除条件时，通常也能使用移动。不要习惯性写 `return std::move(result);`，它可能阻碍具名返回值优化（NRVO）。

## 验证：跟踪三个容器

在课程目录执行：

```bash
mkdir -p build
c++ -std=c++17 -Wall -Wextra -Wpedantic -g demos/09.cpp -o build/demo_09
./build/demo_09
```

预期输出：

```text
copy: Grace
moved: Ada
reused: New value
```

| 时刻 | original | copied | moved |
| --- | --- | --- | --- |
| 创建后 | Ada, Bjarne | 未创建 | 未创建 |
| 拷贝并修改 copied | Ada, Bjarne | Grace, Bjarne | 未创建 |
| 移动后 | 有效，内容未指定 | Grace, Bjarne | Ada, Bjarne |
| original 重新赋值后 | New value | Grace, Bjarne | Ada, Bjarne |

输出没有读取移动后、重新赋值前的 original，因此不依赖某个标准库实现恰好把它变空。

## 局限与常见坑

- 被移动的标准库对象通常可以析构和重新赋值，但不要假设其内容为空。
- `std::move` 不保证更快；类型可能没有移动操作，也可能退化为拷贝。
- 不要对仍需保持原值的对象使用 move。
- 类可以自定义拷贝和移动规则，判断语义时要看类型，而不是只看等号。
- 引用不是新对象；被引用对象销毁后，引用会悬空。

## 三级练习

1. 预测：把 `copied` 改成 `auto& copied = original`，随后改名并移动 original，moved 的第一个元素是什么？
2. 修改：新增一个返回 `std::string` 的函数，直接 `return result;`，不写 `std::move`。
3. 独立：分别写只读接收 `const vector<string>&`、按值接收 `vector<string>` 的函数，用输出验证谁能修改原容器、谁得到副本。

## 完成标准

看到一个赋值或函数参数时，能说出它是副本、别名还是所有权转移；能说明 `std::move` 只允许移动；不读取移动后对象的未指定内容；返回新值时优先直接 return。
