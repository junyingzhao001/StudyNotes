# 09 · 拷贝移动与返回值

[返回学习地图](../README.md) · [下一篇：模板与运行时多态](10-模板与运行时多态.md)

## 本篇目标

区分对象复制、移动和引用，理解 std::move 的实际作用。

## 学习作用

读懂性能相关代码，避免误以为赋值总是共享对象或者 move 总能省开销。

## 核心知识

`auto b = a` 对本例 vector 创建独立副本，修改 b 不会修改 a。`auto& b = a` 则是别名。C++ 的类可以自定义拷贝语义，因此“拷贝”不必然是深拷贝；例如复制 shared_ptr 会共享目标对象。

移动允许类型转移内部资源，减少不必要复制。`std::move(a)` 本身不搬运数据；对于 vector 等类型，目标构造/赋值选择移动操作才进行资源转移。移动 const 对象常退化成拷贝，因为很多移动操作需要修改源对象。

被移动的标准库对象通常仍有效，但状态未指定（另有明确保证的类型除外）。可以销毁或重新赋值；不要假设移动后的 vector 一定为空，也不要不检查就访问它的元素。

返回局部对象时直接 `return result;`。编译器可以进行返回值优化，某些 C++17 场景保证消除拷贝；不满足消除条件时也常能移动。不必写 `return std::move(result);`，这可能阻碍 NRVO。

## Java 对照

```java
List<String> another = original;
```

Java 中这通常复制引用，两个变量看到同一个 List。C++ 的 `auto another = original;` 根据 vector 的值语义复制整个容器；`auto& another = original;` 才是别名。

Java 常由 GC 共享对象，业务复制需要自己设计 copy 方法。C++ 类型直接定义自己的拷贝和移动行为：复制 vector 会得到独立容器，每个元素再按其类型的规则复制；因此 `vector<int>` 的值独立，而 `vector<shared_ptr<T>>` 中的 shared_ptr 仍共享目标。unique_ptr 禁止拷贝。这就是为什么不能只看等号猜成本和所有权，还要看完整类型。

返回值优化（RVO）和具名返回值优化（NRVO）让编译器省掉一些临时对象。入门结论很简单：需要返回一个新值时正常按值返回，让编译器做优化。

源码：[demos/09.cpp](../demos/09.cpp)。从 `C++快速入门` 目录执行：

```bash
mkdir -p build

```

```cpp
#include <iostream>
#include <string>
#include <utility>
#include <vector>

std::vector<std::string> makeNames() {
    std::vector<std::string> result{"Ada", "Bjarne"};
    return result;
}

int main() {
    auto original = makeNames();
    auto copied = original;
    copied.at(0) = "Grace";
    auto moved = std::move(original);
    std::cout << "copy: " << copied.at(0) << '\n';
    std::cout << "moved: " << moved.at(0) << '\n';
    original = {"New value"}; // 重新赋值后再使用
    std::cout << "reused: " << original.at(0) << '\n';
}
```

预期输出：

```text
copy: Grace
moved: Ada
reused: New value
```

## 跟踪三个 vector

| 时刻 | original | copied | moved |
| --- | --- | --- | --- |
| makeNames 后 | Ada, Bjarne | 尚未创建 | 尚未创建 |
| 复制后并修改 copied | Ada, Bjarne | Grace, Bjarne | 尚未创建 |
| 移动到 moved 后 | 有效但内容未指定 | Grace, Bjarne | Ada, Bjarne |
| original 重新赋值后 | New value | Grace, Bjarne | Ada, Bjarne |

代码没有在重新赋值前读取 original，因此不依赖它移动后的具体内容。

## 常见坑

不要给每个表达式都套 std::move。先让所有权与接口清楚，再根据实际性能数据优化。

## 动手练习

1. 预测：将 copied 改为 `auto& copied = original`，在移动前修改它，moved 的第一个元素是什么？
2. 修改：新增一个直接返回 string 的函数，不写 std::move。
3. 独立：分别写一个接收 `const vector<string>&` 的只读函数和一个按值接收的函数，调用后验证谁发生了复制、谁能修改原容器。

## 完成标准

能解释为什么修改 copied 不影响 moved，且不依赖 original 移动后的内容。
