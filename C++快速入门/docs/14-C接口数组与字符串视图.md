## 先说结论

这一篇解决“把 C++ 容器和字符串交给 C、JNI 或系统 API 时，怎样不越界、不悬空”的问题。读完后，你能看懂 `指针 + 长度`、`data()`、`c_str()` 和 `string_view`，并能说清谁拥有数据、借用能持续多久。

它有用，是因为现代 C++ 内部常用 vector 和 string，操作系统、音视频库、OpenGL、JNI/NDK 等边界却经常只接收地址、元素数或 C 字符串。一旦离开拥有数据的类型，“知道长度”和“保活对象”的责任就会回到调用者。

## 问题：一个地址没有携带长度和生命期

Java 的 `int[]` 对象能知道 length，GC 也会为仍被引用的对象维持生命。常见 C/C++ 接口则是：

```cpp
std::int64_t sum(const int* data, std::size_t size);
```

`data` 只表示首元素地址，`size` 的单位由接口约定。本例是 int 元素个数，其他 API 可能要求字节数。只要 `size > 0`，调用者就必须保证对应数量的元素有效；调用期间，这些元素的生命周期和存储地址都要保持有效，不能销毁拥有者，也不能执行会让这段存储失效的修改。

## 方案：把拥有者和视图分开看

| 类型/形式 | 是否拥有数据 | Java 中较接近的直觉 | 关键责任 |
| --- | --- | --- | --- |
| `std::array<int, 3>` | 是，固定 3 个元素 | `int[3]` | 长度是 C++ 类型的一部分 |
| `std::vector<int>` | 是，可增长 | `ArrayList<Integer>` | int 连续存放；扩容可能使旧地址失效 |
| `const int* + size` | 否 | 数组加起止范围 | 调用者保证范围与生命期 |
| `std::string` | 是，可修改、值语义 | String 与 StringBuilder 的部分能力 | 修改可能使旧视图失效 |
| `std::string_view` | 否，只读字符视图 | `CharSequence` 的只读视图直觉 | 不会通过 GC 保活原字符串 |
| `const char*` | 否 | JNI/系统 API 常见边界 | 类型本身不保证末尾有 `\0` |

[完整 demo](../demos/14.cpp) 展示同一份数据怎样以视图传递。关键调用形式是：

```cpp
const std::array<int, 3> scores{80, 90, 100};
sum(scores.data(), scores.size());

const std::string language{"C++17"};
printText(language);              // 转成只读 string_view
const char* cText = language.c_str(); // 借用 NUL 结尾字符序列
```

`array.data()` 返回首元素地址，`array.size()` 返回元素个数。两者必须来自同一段数据，不能拿一个容器的地址配另一个容器的长度。

## string_view：便宜的只读借用

`string_view` 通常只保存地址和长度，不复制字符，也不延长原字符串生命。它适合作为立即读取的函数参数，但保存到成员、返回给调用者或异步使用时必须重新检查生命期。

```text
string language 拥有字符
      │
      ├── string_view ──只借用地址和长度
      └── c_str() ─────借用 NUL 结尾地址

language 销毁或发生使缓冲区失效的修改
      └── 旧 view / 旧指针不能再用
```

不要返回指向局部 string 的 string_view。原 string 被销毁后，view 仍有一个地址，但地址对应的字符已经不再属于它。

## c_str：满足 C 字符串约定

`const char*` 只表示字符指针；只有接口约定它是 C 字符串时，调用者才必须提供可达的结尾 `\0`。`string::c_str()` 提供这个结尾，适合临时传给只读 C API。

普通 `string_view::data()` 不保证视图末尾紧跟 `\0`，不能随意当 C 字符串。`std::string` 还可以包含内嵌 `\0`；依赖 C 字符串的 API 会在第一个 `\0` 处认为文本结束。

## 局限与常见坑

- `data == nullptr` 时，只有接口明确允许空范围且 `size == 0`、实现也不访问 data，调用才可能成立；`sum(nullptr, 1)` 一定不满足本例前提。
- `size_t` 是无符号大小类型。从文本得到的负数要先验证，再转换。
- `size` 的单位可能是元素、字节或字符单元，必须读接口合同。
- UTF-8 中文通常占多个字节；`string::size()` 和 `string_view::size()` 不等于用户看到的字符数。
- vector 扩容、string 修改或拥有者销毁后，旧指针/view 可能失效。
- view 是只读不等于目标不可变化；其他代码修改拥有者时，还要考虑失效和并发同步。

## 三级练习

1. 预测：`sum(nullptr, 0)` 为什么不会进入循环？为什么不能据此调用 `sum(nullptr, 1)`？
2. 修改：用 `vector<int>` 的 `data()` 和 `size()` 调用同一个 sum，并验证总和。
3. 独立：写 `printPrefixBytes(string_view text, size_t byteCount)`；参数明确表示字节数，超长时只打印现有内容。用英文验证正常结果，再用中文 UTF-8 故意截在一个多字节字符中间，观察为什么“字节前缀”不能直接当“用户看到的字符前缀”。
