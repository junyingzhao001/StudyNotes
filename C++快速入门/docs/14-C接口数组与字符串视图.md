## 本篇目标

理解固定数组、`指针 + 长度`、`const char*`、`data()`、`c_str()` 和 `std::string_view`，能安全读懂常见 C API、JNI/NDK 边界代码。

## 学习作用

现代 C++ 项目内部常用 vector 和 string，但操作系统接口、音视频库、JNI、OpenGL 等接口经常接收地址、长度或 C 字符串。实际开发中很容易在这个边界上产生越界和悬空问题。

## Java 对照

Java 的 `int[]` 对象自己知道 length；JNI 把数组交给 native 代码时，则需要通过 JNI API 获取数据和长度。C/C++ API 常直接写成：

```cpp
std::int64_t sum(const int* data, std::size_t size);
```

这里 data 只说明第一个元素在哪里，不自带长度。本例约定 size 是 int 元素个数；另一些 C API 可能要求字节数，必须读接口说明。返回和累计使用 `<cstdint>` 提供的 `std::int64_t`，让这个小例子的求和范围比 int 大，但它仍然有上限。调用者必须保证 `[data, data + size)` 都有效，并且在函数执行期间没有销毁。

| C++ 类型 | 用途 | Java 中较接近的概念 |
| --- | --- | --- |
| `std::array<int, 3>` | 长度编译期固定，按值拥有元素 | `int[3]`，但 C++ array 的长度也是类型的一部分 |
| `std::vector<int>` | 运行期可增长，按值拥有元素 | `ArrayList<Integer>`，但 vector<int> 直接连续存 int |
| `const int* + size` | 借用一段连续数据 | 方法收到数组加起止范围，但 C++ 需自己维护有效性 |
| `std::string` | 拥有可修改字符串 | `StringBuilder` 与 String 的部分能力组合，值语义不同 |
| `std::string_view` | 只读借用一段字符，不拥有 | `CharSequence` 的只读视图感觉，但无 GC 保活 |
| `const char*` | 只读字符指针；接口可约定它指向 C 字符串 | JNI/系统 API 边界常见形式 |

## 核心知识

`std::array<T, N>` 自己拥有 N 个元素，长度不能在运行时改变。`array.data()` 返回第一个元素地址，`array.size()` 返回元素数。这两个值一起传给 C 风格函数。

`std::string_view` 不复制字符，只保存字符位置和长度。它很轻，但不会延长原 string 的生命。不要返回指向局部 string 的 string_view，也不要在原 string 被销毁或发生使缓冲区失效的修改后继续使用旧 view。

`const char*` 这个类型本身只表示只读字符指针，不保证一定存在终止符。只有接口把参数约定为 C 字符串时，调用者才必须提供可达的 `\0`。`string.c_str()` 提供这种结尾，适合临时传给只读 C API；后续修改 string 可能使旧指针失效。std::string 还能包含内嵌 `\0`，许多 C API 会在第一个 `\0` 处截断。普通 string_view 也不保证末尾有 `\0`，所以不能把 `view.data()` 随意当 C 字符串。

## 可运行 demo

源码：[demos/14.cpp](../demos/14.cpp)。从课程目录运行：

```bash
mkdir -p build
c++ -std=c++17 -Wall -Wextra -Wpedantic -g demos/14.cpp -o build/demo_14
./build/demo_14
```

```cpp
#include <array>
#include <cstddef>
#include <cstdint>
#include <iostream>
#include <string>
#include <string_view>

std::int64_t sum(const int* data, std::size_t size) {
    std::int64_t total{0};
    for (std::size_t index{0}; index < size; ++index) {
        total += data[index];
    }
    return total;
}

void printText(std::string_view text) { // 只读借用，不拥有字符
    std::cout << text << " (" << text.size() << " bytes)\n";
}

int main() {
    const std::array<int, 3> scores{80, 90, 100};
    std::cout << "sum: " << sum(scores.data(), scores.size()) << '\n';

    const std::string language{"C++17"};
    printText(language);
    const char* cText = language.c_str();
    std::cout << "C API view: " << cText << '\n';
}
```

预期输出：

```text
sum: 270
C++17 (5 bytes)
C API view: C++17
```

## 常见坑

- data 为 nullptr 时，只有 size 为 0 且函数不解引用它才可能合理；接口约定必须说清楚。
- size 使用 `std::size_t`，不要随意和负数比较；从文本解析出的整数要先验证再转换。
- UTF-8 文本的字节数不是汉字数。string 和 string_view 的 size() 返回字节/字符单元数量。
- Java 的 GC 常能让被引用对象继续存活，string_view 和原始指针做不到。

## 动手练习与完成标准

为 sum 增加空范围调用 `sum(nullptr, 0)`，确认循环不会解引用；不要调用 `sum(nullptr, 1)`。再用 vector 的 data() 和 size() 调用同一个函数。

完成标准：能解释为什么 C 接口常同时传地址和长度，什么时候 c_str 指针会失效，以及 string_view 为什么快但需要生命周期保证。
