# 04 · 指针、生命周期与内存

[返回学习地图](../README.md) · [上一篇：函数引用与 const](03-函数引用与const.md) · [下一篇：类对象与 RAII](05-类对象与RAII.md)

## 先说结论

指针保存的是对象地址，不是对象本身，也不自动拥有对象。你会在可空参数、C 接口、JNI/NDK 和许多底层库中遇到它。

读完本篇，你能看懂 `T*`、`&value`、`*pointer` 和 `nullptr`，能判断一个指针是在借用谁，并避免空指针和悬空指针。最重要的习惯是：每次使用指针前，同时确认“它指向哪里”和“目标现在是否还活着”。

## 问题：地址还在，不代表对象还在

Java 对象变量通常是受 GC 跟踪的引用。只要强引用仍可达，对象通常就继续存活。C++ 原始指针不同：它只是一个地址，保存这个地址不会延长目标对象的生命。

本篇始终使用 `score` 这个整数：

- `score` 是对象，自己拥有数值；
- `observer` 保存 `score` 的地址，只借用它；
- `score` 离开作用域后，`observer` 即使还保留旧地址，也不能再解引用。

这就是为什么“指针不是空的”仍不足以证明它可用。

## 方案一：先分清 `&`、`*` 和 `nullptr`

关键代码来自完整的 [demos/04.cpp](../demos/04.cpp)：

```cpp
int score{80};
int* observer = &score;  // &score 取得地址
*observer = 95;          // 沿地址修改 score

printIfPresent(observer);
printIfPresent(nullptr);
```

同一个符号在不同位置含义不同：

| 写法 | 含义 |
| --- | --- |
| `int* observer` | observer 的类型是“指向 int 的指针” |
| `&score` | 取得 score 的地址 |
| `*observer` | 访问 observer 指向的 int |
| `nullptr` | 当前不指向任何对象 |

`observer` 不是第二个整数。执行 `*observer = 95` 时，真正变化的是 `score`。

## 方案二：用“是否允许为空”选择引用或指针

对于只借用、不接管所有权的函数参数，可以先按下面的规则选择：

| 需求 | C++ 参数 | Java 中较接近的理解 |
| --- | --- | --- |
| 一定存在，只读 | `const T&` | 非 null 对象参数，只读使用 |
| 一定存在，需要修改 | `T&` | 修改调用者传入的对象 |
| 允许为空，只读 | `const T*` | 可为 null 的对象引用 |
| 允许为空，需要修改 | `T*` | 可为 null，并允许修改目标 |

`printIfPresent` 使用 `const int*`，因为“没有值”是合法输入。函数先与 `nullptr` 比较，只有非空时才解引用。

## 方案三：把生命周期画到同一条时间线上

```text
进入 main
  创建 score
  observer 借用 score
  通过 observer 修改并读取 score
离开 main
  observer 与 score 的生命周期结束
```

本例的所有指针使用都发生在 `score` 销毁前，所以借用有效。错误做法是从函数返回局部变量的地址：函数结束时对象已经销毁，返回的指针随即悬空。

原始指针的类型本身不说明谁负责释放。现代 C++ 新代码通常用它表达借用，但旧代码和 C API 可能另有约定。遇到 `T*` 时，应阅读接口说明，不能仅凭星号决定是否 `delete`。

## 补充：`const` 限制的是目标还是指针

- `const int* p`：不能通过 p 修改目标，但 p 可以改指向；
- `int* const p`：p 不能改指向，但可通过它修改非 const 目标。

先从右向左读：`const` 靠近谁，就在限制谁。入门阶段更常见的是 `const T*`，表示“可空的只读借用”。

## 验证：运行现有 demo

在 `C++快速入门` 目录执行：

```bash
mkdir -p build
c++ -std=c++17 -Wall -Wextra -Wpedantic -g demos/04.cpp -o build/demo_04
./build/demo_04
```

预期输出：

```text
value: 95
no value
```

第一行证明 `observer` 修改的是 `score`；第二行证明函数把空值作为正常分支处理，而不是直接解引用。

## 常见坑

- 解引用 `nullptr`、悬空指针或越界地址会产生未定义行为；这类错误不保证立即崩溃。
- 不要对局部对象的地址调用 `delete`。`score` 不是通过 `new` 创建的，也不由 `observer` 拥有。
- 指针非空不代表目标还活着。
- `vector` 扩容可能搬动元素，使旧指针、引用和迭代器失效；第 07 篇会继续说明。
- 需要拥有动态对象时，优先使用第 06 篇的智能指针，而不是手写 `new/delete`。
