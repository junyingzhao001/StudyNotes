# 04 · 指针生命周期与内存

[返回学习地图](../README.md) · [下一篇：类对象与RAII](05-类对象与RAII.md)

## 本篇目标

理解地址、解引用、nullptr、借用和悬空问题。

## 学习作用

读懂底层接口、树形结构、NDK 风格代码，避免把地址当成对象所有权。

## 核心知识

### 1. 地址和解引用

指针保存对象地址：表达式 `&value` 取地址，`*ptr` 访问指针指向的对象。声明 `int* ptr` 中的星号表示指针类型；表达式 `*ptr` 的星号表示访问目标。这是同一个字符在两种位置的用途。

### 2. 可空借用

指针可以重新指向，也可以用 `nullptr` 表示不指向对象。解引用前必须从接口约定或判断中确认它不为空。引用适合“必须有对象”，指针适合“允许没有对象”或 C 接口要求地址的场景。

### 3. 生命周期

引用与指针都能借用对象。与常见 Java 对象引用相比，C++ 原始指针没有垃圾回收托底；拿着一个地址，不会让目标对象自动继续存活。局部对象通常在离开作用域时销毁，指向它的地址随即失效。

不要解引用空指针、已释放对象的指针或越界位置；这些可能触发未定义行为。未定义行为不保证立即崩溃，程序也可能看似正常。

### 4. const 在谁身上

`const int* p` 不允许通过 p 修改目标，但可以让 p 改指向；`int* const p` 不允许 p 改指向，但可修改非 const 目标。入门阶段把原始指针默认理解为借用；需要拥有动态对象时使用第 06 篇的智能指针。

原始指针类型本身不编码所有权。现代新代码通常把它当借用，但旧代码和 C API 可能另有释放约定；阅读接口文档与调用者/被调用者的契约，不能仅凭 `T*` 判断是否应该 delete。

## Java 对照

Java 对象变量可以为 null，GC 还会因为强引用存在而保持对象存活。C++ 原始指针也可以为 nullptr，但它通常只是观察者：指针存在并不会阻止目标对象析构。Java 很少直接看到对象地址，C++ 对接系统、JNI、OpenGL 或 C API 时会频繁出现地址与长度。

可以先用这张选择表：

| 需求 | C++ 参数 |
| --- | --- |
| 一定存在，只读 | `const T&` |
| 一定存在，需要修改 | `T&` |
| 允许为空，只读 | `const T*` |
| 允许为空，需要修改 | `T*` |

## 可运行 demo

源码：[demos/04.cpp](../demos/04.cpp)。从 `C++快速入门` 目录执行：

```bash
mkdir -p build
c++ -std=c++17 -Wall -Wextra -Wpedantic -g demos/04.cpp -o build/demo_04
./build/demo_04
```

```cpp
#include <iostream>

void printIfPresent(const int* value) {
    if (value != nullptr) {
        std::cout << "value: " << *value << '\n';
    } else {
        std::cout << "no value" << '\n';
    }
}

int main() {
    int score{80};
    int* observer = &score; // 借用 score，不负责释放
    *observer = 95;
    printIfPresent(observer);
    printIfPresent(nullptr);
    // observer 和 score 的使用都在 score 的生命周期内。
}
```

预期输出：

```text
value: 95
no value
```

## 画出 demo 中的关系

```text
score 对象（值 80 → 95）
   ▲
   │ 地址
observer ───────────┘
```

observer 自己不是第二个 int，也不拥有 score。`*observer = 95` 沿地址修改 score。第一次 print 收到同一地址并输出 95；第二次收到 nullptr，先判断后走 no value 分支。main 结束前 score 始终存活，所以第一次借用有效。

## 常见坑

不能对局部对象地址使用 delete。vector 扩容可能使旧指针、引用和迭代器失效；使用前应确认容器操作是否会使它们失效。
