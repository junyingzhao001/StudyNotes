# 02 · 类型、初始化与常用语法

[返回学习地图](../README.md) · [上一篇：作用域、头文件与宏定义](01A-作用域头文件与宏定义.md) · [下一篇：函数、引用与 const](03-函数引用与const.md)

## 先说结论

现代 C++ 代码应让变量从创建时就拥有有效值，并让类型表达限制。`{}` 初始化、`const`、`auto` 和显式转换共同解决未初始化、意外改值、类型猜错和整数除法等日常问题。

读完本篇，你能看懂一段“保存分数、求和、计算平均值、判断等级”的代码，能说出每个变量的实际类型，并写出不会被整数除法截断的平均值计算。这些语法会出现在后面每一个 demo 和真实项目中。

## 问题：代码能编译，不代表数值符合预期

用整数分数 80、90、100 求平均值，看起来只需要相加再除以数量。但 C++ 中至少要回答四个问题：

1. 累加变量创建时有没有有效初值？
2. `auto` 最终推导成什么类型？
3. 除法发生在整数之间，还是浮点数之间？
4. 分数列表是否可能为空？

在 C++17 中，读取未初始化的局部基础类型，例如先写 `int sum;` 再读取 sum，会产生未定义行为。把初始化写在声明处，能让数据从第一行起就处于有效状态。

## 方案：让初始化和类型共同表达计算意图

关键代码来自完整的 [demos/02.cpp](../demos/02.cpp)：

```cpp
std::vector<int> scores{80, 90, 100};
auto sum = 0;
for (int score : scores) {
    sum += score;
}
const double average =
    static_cast<double>(sum) / scores.size();
```

这段代码按“准备数据—累加—转换—除法”的顺序工作：

- `scores{80, 90, 100}` 创建并初始化一个整数 vector；
- `auto sum = 0` 根据右侧的 `0` 推导出 int；
- 范围 for 依次把每个 int 复制给局部变量 score；
- `static_cast<double>(sum)` 先把一个操作数转成 double；
- 之后的除法按浮点数计算，结果保存进只读变量 average。

若写 `sum / scores.size()`，两个操作数都是整数类型，小数部分会先被截掉，再转换成 double。显式转换必须发生在除法之前。

真实输入还应先处理空列表：

```text
scores 为空 → 没有可计算的平均值，走单独分支
scores 非空 → 求和，再除以 size()
```

本 demo 使用固定的非空数据，所以输出路径确定；练习会让你补上空输入分支。

## 花括号、const 和 auto 分别解决什么

### `{}`：创建时给出有效值

`int count{0};` 明确从 0 开始。花括号还能拒绝许多窄化转换，例如 `int count{3.5};` 在编译阶段报错，避免静默丢掉小数。

花括号和圆括号对容器可能含义不同：

- `vector<int>{3, 7}` 表示两个元素：3 和 7；
- `vector<int>(3, 7)` 表示三个元素，每个都是 7。

不能只为了统一风格而机械互换。

### `const`：初始化后不再通过该变量修改

`const double average` 表示后续代码不能给 average 重新赋值。对类和容器，C++ const 通常还会阻止调用普通修改方法。

### `auto`：由初始化表达式推导静态类型

`auto` 不是动态类型。`auto sum = 0` 的 sum 从编译时起就是 int，之后不能改成 string 或 double。读代码时仍要看右侧表达式，判断推导结果。

## 范围 for 和 enum class

`for (int score : scores)` 每轮得到一个 int 副本；修改 score 不会改 vector 中的元素。第 03 篇会说明何时用引用避免复制或修改原元素。

完整 demo 还使用 `enum class Level { Beginner, Advanced };`。它创建带作用域的枚举值，调用时写 `Level::Beginner`，避免 Beginner 这样的名字散落到外层作用域。demo 把当前学习等级设为 Beginner，并将它与平均分条件一起判断。

## Java/Kotlin 对照

| Java/Kotlin | C++17 | 关键差别 |
| --- | --- | --- |
| `var n = 3` | `auto n = 3` | 都是编译期推导，不是动态类型 |
| `final int n` / Kotlin `val n` | `const int n` | 对基础值都限制后续重新赋值 |
| `final List<T>` | `const std::vector<T>` | Java final 固定引用，List 内容仍可能改变；C++ const vector 不能调用普通修改方法 |
| `List<Integer>` | `std::vector<int>` | vector 直接存 int，没有 Integer 装箱 |
| 强制类型转换 | `static_cast<T>(value)` | C++ 常用 static_cast 明确表达转换目标 |
| 增强 for | 范围 for | C++ 可明确选择元素副本或引用 |

`scores.size()` 的类型通常是 `std::size_t`，用于表示对象大小和索引。入门时可以写 `auto size = scores.size();`。把它与可能为负的 int 混合比较前，应先确认数据范围和转换规则。

## 常见坑

- 声明局部 int 后不初始化就读取；在 C++17 中这是未定义行为。
- 先做整数除法，再把结果赋给 double；被截掉的小数无法恢复。
- 对空 vector 直接计算平均值；应先定义“没有分数”时的业务结果。
- 认为 auto 会让变量运行时改变类型。
- 把 Java 的 final List 直接类比成 C++ const vector，两者对容器内容的限制不同。
- 混淆 `vector<int>{3, 7}` 与 `vector<int>(3, 7)`。
