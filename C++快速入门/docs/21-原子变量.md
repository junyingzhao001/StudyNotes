# 21 · 原子变量

[返回学习地图](../README.md) · [下一篇：后台任务执行器项目](22-后台任务执行器项目.md)

## 本篇目标

使用 `std::atomic` 保护简单计数器，理解 atomic 能解决的范围，以及它和 mutex、volatile 的区别。

## 学习作用

计数、状态标志等单一值经常被多线程访问。atomic 提供不可分割的读写/读改写操作，但它不会自动保护容器或跨多个字段的业务规则。

## Java 对照

Java `AtomicInteger` 比 Java volatile 更接近 `std::atomic<int>`。Java volatile 带有语言定义的线程可见性与顺序规则；C++ volatile 主要用于特殊内存访问，不能作为线程同步工具。不要把 Java volatile 用法直接翻译成 C++ volatile。

```cpp
std::atomic<int> counter{0};
++counter;             // 原子的读-改-写
int value = counter.load();
```

本篇使用默认内存顺序，也就是顺序一致语义。`memory_order_relaxed`、acquire/release 等能进一步调整约束，但错误使用很难排查；先在确有性能证据和完整同步设计时再学习。

## atomic 的边界

下面的独立 ++ 可以由 atomic 保护，但“如果余额足够就扣款”、同时更新两个字段、vector.push_back 等复合不变量通常仍需要 mutex。即使每个字段都是 atomic，多个操作组合起来也不自动成为一个事务。

atomic 也不管理被指针指向对象的生命周期。`atomic<T*>` 只能原子地处理指针值，目标是否仍存活仍需另一套所有权方案。

## 可运行 demo

源码：[demos/21.cpp](../demos/21.cpp)：

```bash
c++ -std=c++17 -Wall -Wextra -Wpedantic -g -pthread \
  demos/21.cpp -o build/demo_21
./build/demo_21
```

```cpp
#include <atomic>
#include <iostream>
#include <thread>
#include <vector>

class JoiningThreads {
public:
    explicit JoiningThreads(std::vector<std::thread>& threads) : threads_(threads) {}
    ~JoiningThreads() {
        for (auto& thread : threads_) {
            if (thread.joinable()) thread.join();
        }
    }

    JoiningThreads(const JoiningThreads&) = delete;
    JoiningThreads& operator=(const JoiningThreads&) = delete;

private:
    std::vector<std::thread>& threads_;
};

int main() {
    std::atomic<int> counter{0};
    {
        std::vector<std::thread> workers;
        JoiningThreads joining{workers};
        for (int index{0}; index < 4; ++index) {
            workers.emplace_back([&counter] {
                for (int repeat{0}; repeat < 5000; ++repeat) ++counter;
            });
        }
    }
    std::cout << "counter: " << counter.load() << '\n';
}
```

预期输出：

```text
counter: 20000
```

每次增加都是原子操作，JoiningThreads 在离开内部作用域时 join 全部线程，main 随后读取，结果稳定。这个 RAII guard 还保证线程创建中途失败时，已经创建的线程不会以 joinable 状态直接析构。与第 18 篇相比，这里只有一个独立计数器，没有需要一起维护的容器和业务状态。

## 常见坑

- `volatile int` 不能替代 atomic，也不能修复数据竞争。
- `counter = counter + 1` 是一次原子 load 加一次原子 store，组合不保证等价于原子递增；使用 ++ 或 fetch_add。
- atomic 类型不代表围绕它的整个类都线程安全。
- ASan/UBSan 不检查普通数据竞争；可选的 ThreadSanitizer 必须单独构建，且不能和 ASan 混用。

## 三级练习与完成标准

1. 预测：四条线程循环次数分别改为 1、2、3、4，最终计数是多少？
2. 修改：使用 fetch_add(1) 代替 ++，保持默认内存顺序。
3. 设计：一个账户包含 balance 和 lastTransactionId，解释为什么两个 atomic 仍不一定维护“一次交易同时更新两个字段”的不变量，并给出 mutex 方案。

完成标准：能判断简单独立值何时适合 atomic，复合状态何时应使用 mutex，并明确 C++ volatile 与线程同步无关。
