# 11 · 错误处理与文件读写

[返回学习地图](../README.md) · [下一篇：多文件与综合项目](12-多文件与综合项目.md)

## 本篇目标

会处理 optional、异常和文件流状态，理解失败也是接口的一部分。

## 学习作用

让程序正确面对空数据、非法输入和文件打开失败，而不是仅跑通成功路径。

## 核心知识

`std::optional<T>` 表达“可能有一个 T”，适合查不到等预期情况；使用前检查是否有值。异常用于接口约定的失败情况，本例使用 invalid_argument 表达非法调用参数。不同项目可能禁用异常，需要遵循项目约定。

`try` 中抛出的异常由匹配的 catch 处理；一般用 `catch (const std::exception& e)` 避免复制并保留多态信息。异常传播时，已经构造完成的局部对象会按规则析构，这是 RAII 能避免资源泄漏的原因。

fstream 默认常通过状态位报告失败，不会在所有失败时自动抛异常。打开后检查流，写入并关闭后也检查结果；逐行读取用 `while (std::getline(input, line))`，不要用 `while (!input.eof())`。

相对文件路径基于运行程序时的工作目录，不是 cpp 所在目录。本例要求传入新文件路径，拒绝覆盖已有文件，适合本地学习；这不是面对并发竞争的安全独占创建实现。

## 先按失败含义选择表达方式

| 情况 | C++ 常见表达 | 例子 |
| --- | --- | --- |
| 没找到是正常结果 | optional、bool、迭代器 end | 查询可能不存在的任务 |
| 当前操作不能完成 | 异常或项目统一的错误类型 | 非法参数、文件无法打开 |
| 流操作失败 | 检查流状态，必要时转成异常 | ifstream/ofstream |
| 整个进程成功/失败 | main 返回 0/非 0 | 脚本和 CI 据此判断 |

不同 C++ 项目可能使用异常、错误码、expected 风格类型或组合。进入已有项目先遵循它的错误约定，不要在同一层随意混用。

## Java 对照

Java `Optional<T>` 与 C++ optional 用途接近；Java 的 checked exception 在 C++ 中没有对应的强制声明检查。Java try-with-resources 显式划出资源作用域，C++ 文件流离开作用域就会析构，但写文件仍要检查 flush/close 阶段是否失败。

Java `main(String[] args)` 对应 C++ 的 `int main(int argc, char* argv[])`：argc 是参数数量，argv 是参数字符串数组，argv[0] 通常是程序名。本 demo 因此要求 argc 等于 2。

## 可运行 demo

源码：[demos/11.cpp](../demos/11.cpp)。从 `C++快速入门` 目录执行：

```bash
mkdir -p build
c++ -std=c++17 -Wall -Wextra -Wpedantic -g demos/11.cpp -o build/demo_11
./build/demo_11 "$(mktemp -d)/notes.txt"
```

`mktemp -d` 创建一个临时目录，后面的 `/notes.txt` 是尚不存在的新文件路径，正好满足 demo 的约定。`std::filesystem::path` 用一个类型保存和操作路径，它不表示文件已经存在。

```cpp
#include <filesystem>
#include <fstream>
#include <iostream>
#include <optional>
#include <stdexcept>
#include <string>

std::optional<int> firstScore(bool available) {
    if (!available) return std::nullopt;
    return 80;
}

int main(int argc, char* argv[]) {
    try {
        if (argc != 2) throw std::invalid_argument("usage: demo NEW_OUTPUT_FILE");
        const std::filesystem::path path{argv[1]};
        if (std::filesystem::exists(path)) throw std::runtime_error("file already exists");
        {
            std::ofstream output(path);
            if (!output) throw std::runtime_error("cannot open output");
            output << "C++17 file demo" << '\n';
            output.close();
            if (!output) throw std::runtime_error("cannot finish writing");
        }
        std::ifstream input(path);
        if (!input) throw std::runtime_error("cannot open input");
        std::string line;
        while (std::getline(input, line)) std::cout << line << '\n';
        if (!input.eof() || input.bad()) throw std::runtime_error("cannot finish reading");
        const auto score = firstScore(false);
        std::cout << "score: " << score.value_or(0) << '\n';
    } catch (const std::exception& error) {
        std::cerr << "error: " << error.what() << '\n';
        return 1;
    }
}
```

预期输出：

```text
C++17 file demo
score: 0
```

## 成功路径和失败路径

成功时：检查参数 → 确认文件不存在 → 打开并写入 → 显式 close 后检查 → 重新打开并逐行读取 → optional 为空时用 0 → 返回 0。

失败时，throw 立刻离开当前语句，已构造的局部对象在栈展开中析构，catch 输出 error 并返回 1。fstream 默认并非每次失败都 throw，所以代码在打开、关闭和读取结束后主动检查状态。

getline 遇到正常文件结尾会设置 eof 状态，因此循环结束不自动代表错误；bad 通常表示更严重的底层读写失败。本例在循环后确认“确实是正常到达 EOF，且没有 bad”，再把读取视为成功。

## 常见坑

调用 optional.value() 前不检查可能抛异常；用 *optional 前也必须保证有值。catch 后不要吞掉错误并假装成功。

## 动手练习

3. 独立：写 `optional<int> parsePositiveInt(const string&)`，让空串、负数和非法字符返回 nullopt；为至少四组输入写检查。
