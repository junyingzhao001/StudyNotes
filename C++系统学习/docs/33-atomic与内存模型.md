# 33 · atomic 与内存模型入门

## 先说这篇讲什么

这篇讲单个计数或标志怎样无数据竞争地读写，以及为什么多个原子操作不自动组成业务事务。

## 它有什么用

简单计数器用 mutex 可能过重，但错误使用 atomic 又会让跨字段规则失效。先掌握默认顺序，再按测量结果深入。

## 要解决的问题

`if (count > 0) --count` 即使 count 是 atomic，检查和递减仍是两步，其他线程可以插入。

## 先把几个词说清楚

- **原子操作**：其他线程不会看到它执行到一半
- **读改写**：一次完成读取、计算和写回
- **内存顺序**：原子操作如何约束其他内存访问的可见顺序

## 一个案例

只统计已处理任务总数，线程之间没有其他关联状态，使用 atomic<int>::fetch_add 合适。

```cpp
std::atomic<int> processed{0};
// 每个 worker 完成一个任务后
processed.fetch_add(1);
std::cout << processed.load() << '\n';
```

## 常用 API 和作用

| API / 规则 | 用来做什么 |
| --- | --- |
| `atomic<T>` | 支持特定 T 的原子访问 |
| `load/store` | 原子读取和写入 |
| `fetch_add` | 一次原子加法 |
| `compare_exchange` | 仅当值符合预期时更新 |

## 怎么验证自己真的理解了

多个线程各增加固定次数，最终必须等于线程数乘次数，并用 TSan 确认实际路径无竞争报告。

## 常见坑

- C++ volatile 不负责线程同步。
- atomic 保护的是单次操作，不自动保护 vector 或多字段不变量。
- 不要在没有证据时改用宽松内存序；默认顺序更容易正确。

## 马上动手

列出项目中的计数、停止标志和复合状态，判断哪些可用 atomic，哪些必须用 mutex。

## 学完标准

能为独立计数使用 atomic，并识别需要跨多步一致性时仍应使用锁。
