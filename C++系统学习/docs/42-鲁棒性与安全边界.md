# 42 · 鲁棒性与安全边界

[返回学习地图](../README.md) · [上一篇](41-性能分析与内存成本.md) · [下一篇](43-综合项目网络任务服务.md)

## 先说这篇讲什么

这篇讲把外部输入当作不可信数据，为长度、数量、时间和资源设置上限。

## 它有什么用

文件、网络和命令行输入都可能损坏或恶意构造。安全不是最后补一个 if，而是每个边界都先验证再分配或访问。

## 要解决的问题

一个长度字段可能溢出、超大或与实际数据不符。若先分配再校验，检查已经太晚。

## 先把几个词说清楚

- **信任边界**：数据从外部进入当前程序的位置
- **整数溢出**：结果超出类型能表示的范围
- **资源耗尽**：内存、线程、文件或队列被输入持续占满

## 一个案例

协议正文最大 1MB。先读取固定长度头，转成无符号大小前检查范围，再验证剩余字节足够，最后才分配。

```cpp
if (length < 0 || length > kMaxMessage)
    return Error::invalid_length;
std::vector<std::byte> body(static_cast<size_t>(length));
```

## 常用 API 和作用

| API / 规则 | 用来做什么 |
| --- | --- |
| `size/limit 检查` | 在分配和循环前限制规模 |
| `checked conversion` | 转换前确认范围和符号 |
| `timeout/cancellation` | 限制等待时间 |
| `fuzzing` | 自动生成大量异常输入寻找崩溃 |

## 怎么验证自己真的理解了

测试负数、0、最大值、最大值加 1、截断输入和大量连续小请求。

## 常见坑

- `a + b <= limit` 本身也可能先溢出，可改成 `a <= limit - b` 并先验证范围。
- 不要把内部异常或路径原样回给远程用户。
- 限制要分连接、分用户和全局多层设置。

## 马上动手

为文件和网络入口各写一张限制表：最大长度、数量、时间、并发和错误响应。

## 学完标准

能在分配、转换和访问前验证输入，并为资源使用设置明确上限。
