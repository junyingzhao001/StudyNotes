# 40 · 网络服务测试与可靠性

[返回学习地图](../README.md) · [上一篇](39-UDP-HTTP与TLS.md) · [下一篇](41-性能分析与内存成本.md)

## 先说这篇讲什么

这篇讲怎样在本机自动测试网络服务，并覆盖断线、超时、坏包和重连。

## 它有什么用

手工启动两个终端只能证明一次成功路径。可靠服务需要可重复地制造失败，并保证测试不会永久挂住。

## 要解决的问题

真实网络故障难稳定复现。测试应在 loopback 上控制服务端和客户端，用短但合理的超时等待明确状态。

## 先把几个词说清楚

- **loopback**：只在本机内部通信的地址
- **故障注入**：主动制造断线、慢响应或坏数据
- **退避**：重试间隔逐渐增加，避免持续轰击

## 一个案例

测试创建服务端并监听系统分配端口，客户端发一条请求；另一个测试只发半个包后断开，服务端仍可接受下一连接。

```cpp
server.listen(0);
auto port = server.localPort();
Client client{"127.0.0.1", port};
CHECK(client.request("ping") == "pong");
```

## 常用 API 和作用

| API / 规则 | 用来做什么 |
| --- | --- |
| `127.0.0.1 / ::1` | IPv4/IPv6 本机地址 |
| `端口 0` | 让系统选择空闲监听端口 |
| `future/condition_variable` | 测试中等待可观察状态 |
| `deadline` | 为整个测试设置结束时间 |

## 怎么验证自己真的理解了

将成功、坏包、超时、重连、服务端关闭各运行多次，并为整个测试设置超时。

## 常见坑

- 不要写死常用端口，测试并行时会冲突。
- 不要靠固定 sleep 判断服务已启动，应等待明确就绪信号。
- 重试必须有上限、退避和可取消机制。
