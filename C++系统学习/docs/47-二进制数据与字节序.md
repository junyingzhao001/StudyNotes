# 47 · 二进制数据、位运算与字节序

## 先说这篇讲什么

这篇讲协议和文件格式中的原始字节、整数编码、对齐与字节序。

## 它有什么用

网络、音视频和硬件接口都以字节工作。直接写对象内存会受填充、字节序和编译器布局影响。

## 要解决的问题

同一个 32 位整数在不同字节序机器上内存排列可能不同，结构体还可能插入填充字节。

## 先把几个词说清楚

- **字节序**：多字节整数先放高位还是低位字节
- **对齐**：对象地址满足硬件访问要求
- **填充**：编译器为对齐在成员间加入的空字节

## 一个案例

协议长度固定为网络大端 32 位。编码函数逐字节写入，解码先检查至少有 4 字节。

```cpp
uint32_t value = 0x01020304;
std::array<std::byte, 4> out{
    std::byte(value >> 24), std::byte(value >> 16),
    std::byte(value >> 8),  std::byte(value)};
```

## 常用 API 和作用

| API / 规则 | 用来做什么 |
| --- | --- |
| `std::byte` | 表达原始字节而非字符或数字 |
| `std::endian` | 查询本机字节序 |
| `bitset/位运算` | 处理标志位 |
| `memcpy` | 在允许的类型与边界内复制字节 |

## 怎么验证自己真的理解了

编码固定值并检查四个字节，再解码回原值。测试截断输入和最大值。

## 常见坑

- 不要通过不相关类型指针强行重解释对象，可能违反别名和对齐规则。
- 不要把结构体 sizeof 字节直接当稳定文件格式。
- 移位前确认类型宽度和符号。

## 马上动手

实现大端 uint32 的 encode/decode，并为 0、最大值和短输入写测试。

## 学完标准

能定义与平台无关的二进制格式，并安全处理长度和字节序。
