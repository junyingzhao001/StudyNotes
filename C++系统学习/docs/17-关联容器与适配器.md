# 17 · 关联容器与容器适配器

[返回学习地图](../README.md) · [上一篇](16-顺序容器.md) · [下一篇](18-算法迭代器与ranges.md)

## 先说这篇讲什么

这篇根据“按键查找、是否有序、是否允许重复”选择 map、unordered_map、set 和队列类容器。

## 它有什么用

查用户、统计词频、维护去重集合和优先任务都需要不同数据结构。选择依据比记方法名更重要。

## 要解决的问题

用 map 的 `operator[]` 查询不存在的键会顺便插入新元素；依赖 unordered_map 遍历顺序也会产生不稳定行为。

## 先把几个词说清楚

- **键值容器**：通过 key 找到 value
- **有序**：遍历时按比较规则排列
- **适配器**：在底层容器上限制成栈、队列等接口

## 一个案例

词频统计不需要顺序时使用 unordered_map；输出报告前若要求按字母排序，可转入 vector 后排序。

```cpp
std::unordered_map<std::string, int> counts;
for (const auto& word : words) ++counts[word];
if (auto it = counts.find("cpp"); it != counts.end())
    std::cout << it->second << '\n';
```

## 常用 API 和作用

| API / 规则 | 用来做什么 |
| --- | --- |
| `map` | 按键有序，查找通常为对数复杂度 |
| `unordered_map` | 哈希查找，不保证遍历顺序 |
| `set/unordered_set` | 只保存不重复的键 |
| `queue/stack/priority_queue` | 先进先出、后进先出、最高优先级先出 |

## 怎么验证自己真的理解了

确认 find 不会改变 size，再用 `counts["missing"]` 查询并观察 size 增加。

## 常见坑

- 只读查询优先 find、contains 或 at，不要无意间用 [] 插入。
- unordered 容器 rehash 会使迭代器失效。
- priority_queue 默认最大值优先，不是最小值优先。

## 马上动手

实现任务 id 到 Task 的查找表，再增加一个按优先级取任务的 priority_queue。

## 学完标准

能根据有序性、查找和重复需求选择容器，并安全处理不存在的键。
