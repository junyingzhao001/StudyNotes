# 53 · 数据库访问

## 先说这篇讲什么

这篇用 SQLite 的 C API 说明数据库访问，重点是 prepared statement、事务和连接生命周期。其他数据库客户端名字不同，但责任相同。

## 它有什么用

数据库操作会失败、超时或只完成一部分。事务让一组修改一起成功或一起回滚。

## 要解决的问题

把用户输入拼进 SQL 会产生注入风险；更新多张表却不使用事务会留下不一致状态。

## 先把几个词说清楚

- **prepared statement**：把 SQL 结构和参数值分开
- **事务**：一组操作作为整体提交或回滚
- **迁移**：版本化地修改数据库结构

## 一个案例

完成任务同时写审计记录，两条 SQL 在同一事务中执行。任意一步失败都回滚。

```cpp
Transaction tx{connection};
updateTask(tx, id, Done{});
insertAudit(tx, id, "completed");
tx.commit();
```

## 常用 API 和作用

| API / 规则 | 用来做什么 |
| --- | --- |
| `sqlite3_prepare_v2` | 把 SQL 编译成可重复执行的 statement |
| `sqlite3_bind_* / sqlite3_step` | 绑定参数并执行或读取一行结果 |
| `sqlite3_finalize` | 释放 statement；适合用 RAII 包装 |
| `begin/commit/rollback` | 控制事务 |
| `connection pool` | 复用有限连接 |
| `migration` | 按版本升级 schema |

## 怎么验证自己真的理解了

制造第二条写入失败，确认任务状态没有单独提交。另测试包含引号的标题由参数绑定安全保存。

## 常见坑

- 不要字符串拼接 SQL 参数。
- 连接和事务都需要 RAII，异常路径要回滚。
- 重试前先确认操作是否幂等及事务是否已经提交。

## 马上动手

为一项跨两张表的业务写事务边界和失败测试。

## 学完标准

能使用参数化语句和 RAII 事务，并处理超时、回滚和迁移。
