# 12 · 智能指针与所有权

[返回学习地图](../README.md) · [上一篇](11-拷贝移动与特殊成员.md) · [下一篇](13-继承与运行时多态.md)

## 先说这篇讲什么

这篇讲动态对象的所有权。默认先用值对象，确实需要动态生命周期时再选择智能指针。

## 它有什么用

智能指针把“谁负责销毁”写进类型，能减少内存泄漏、重复释放和跨模块所有权不清。

## 要解决的问题

裸指针既可能表示借用，也可能表示拥有，单看类型很难知道谁该 delete。unique_ptr 明确只有一个所有者。

## 先把几个词说清楚

- **独占所有权**：同一时刻只有一个负责销毁的所有者
- **共享所有权**：多个所有者共同维持对象生命
- **弱引用**：观察共享对象但不延长它的生命

## 一个案例

Controller 独占一个 Service，其他函数只在调用期间借用 Service。这里 unique_ptr 加短期引用比到处使用 shared_ptr 更清楚。

```cpp
auto owner = std::make_unique<Service>();
Service& borrowed = *owner;
borrowed.run();
auto next = std::move(owner);
```

## 常用 API 和作用

| API / 规则 | 用来做什么 |
| --- | --- |
| `make_unique<T>` | 创建独占动态对象 |
| `unique_ptr<T>` | 表达唯一所有者，可移动不可复制 |
| `make_shared<T>` | 一次分配创建共享对象 |
| `weak_ptr<T>` | 打破 shared_ptr 循环并在使用前 lock |

## 怎么验证自己真的理解了

移动后确认 owner 为空、next 非空。画出借用在 next.reset() 前后是否有效。

## 常见坑

- `get()` 只借出地址，不要把它交给另一个智能指针重新拥有。
- shared_ptr 引用计数线程安全不代表对象字段线程安全。
- 相互持有 shared_ptr 会形成循环，常需把反向关系改为 weak_ptr。

## 马上动手

为一组父子对象关系画所有权图，并解释哪些边是拥有、哪些边是借用。

## 学完标准

能根据关系选择值、引用、unique_ptr、shared_ptr 或 weak_ptr，而不是默认 shared_ptr。
