## 先说这篇讲什么

这篇比较 array、vector、deque 和 list。重点不是背全部方法，而是按存储方式和访问需求选择。

## 它有什么用

大部分项目数据都放在容器中。选对容器能让代码简单，并决定元素地址是否容易因修改失效。

## 要解决的问题

默认选择 list 往往失去连续内存和随机访问优势。多数可变序列先用 vector，只有明确需求再换。

## 先把几个词说清楚

- **size**：当前元素数量
- **capacity**：vector 当前已预留的容量
- **失效**：旧迭代器、引用或指针不能再使用

## 一个案例

任务列表需要顺序遍历、按下标查看和尾部追加，因此使用 vector。预估数量时 reserve 可减少扩容。

```cpp
std::vector<Task> tasks;
tasks.reserve(100);
tasks.push_back(Task{1, "learn"});
const Task& first = tasks.at(0);
```

## 常用 API 和作用

| API / 规则 | 用来做什么 |
| --- | --- |
| `vector` | 连续存储、默认首选动态序列 |
| `array` | 编译期固定长度的连续数组 |
| `deque` | 两端增删方便，不保证整体连续 |
| `list` | 节点链表，特定插入/稳定性需求才考虑 |

## 怎么验证自己真的理解了

打印 size 和 capacity，继续 push_back 直到扩容，解释为什么扩容前保存的元素引用可能失效。

## 常见坑

- reserve 只改容量，不创建元素；resize 会改变元素数量。
- `vector<int>{3, 7}` 是两个元素，`vector<int>(3, 7)` 是三个 7。
- operator[] 不检查越界，at 会检查并抛异常。

## 马上动手

为任务列表实现 add、remove 和 find，先使用 vector，不提前优化。

## 学完标准

能说明为什么默认选 vector，并知道哪些修改需要重新检查旧借用。
