# 51 · 协程与异步网络

[返回学习地图](../README.md) · [上一篇](50-额外同步工具.md) · [下一篇](52-系统与进程接口.md)

## 先说这篇讲什么

这篇用 Asio 协程解释 co_await：函数暂停，把线程还给事件循环，操作完成后从原位置继续。

## 它有什么用

多步异步流程用回调容易层层嵌套。协程让控制流更接近顺序代码，但对象生命周期和取消仍然存在。

## 要解决的问题

协程暂停不等于阻塞线程，也不自动保活所有引用。局部状态通常保存在协程帧中，外部借用仍需检查。

## 先把几个词说清楚

- **协程帧**：保存暂停点和局部状态的对象
- **awaitable**：可以被 co_await 等待的操作
- **挂起**：暂时停止协程而不占住线程

## 一个案例

会话协程循环读取一帧、处理、写响应。每次网络等待时事件循环可处理其他连接。

```cpp
asio::awaitable<void> session(tcp::socket socket) {
    for (;;) {
        auto message = co_await readFrame(socket);
        co_await writeFrame(socket, handle(message));
    }
}
```

## 常用 API 和作用

| API / 规则 | 用来做什么 |
| --- | --- |
| `co_await` | 等待异步结果并允许协程挂起 |
| `co_return` | 结束协程并返回结果 |
| `asio::awaitable<T>` | Asio 协程返回类型 |
| `co_spawn/use_awaitable` | 启动协程并选择 awaitable 风格 |

## 怎么验证自己真的理解了

同时连接多个客户端，其中一个故意慢。确认慢连接等待时其他连接仍有响应，并测试取消。

## 常见坑

- 不要在协程中执行阻塞文件或长 CPU 工作。
- 捕获引用在协程挂起期间也可能悬空。
- 异常会沿 await 链传播，启动边界必须观察它。

## 马上动手

## 学完标准

能解释协程与线程的区别，并安全处理协程中的生命周期、异常和取消。
