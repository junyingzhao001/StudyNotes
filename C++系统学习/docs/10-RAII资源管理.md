# 10 · RAII 资源管理

[返回学习地图](../README.md) · [上一篇](09-构造析构与对象生命周期.md) · [下一篇](11-拷贝移动与特殊成员.md)

## 先说这篇讲什么

这篇讲 RAII：对象构造成功就代表资源可用，对象析构时自动释放资源。

## 它有什么用

函数可能正常返回、提前 return 或抛异常。把关闭文件、释放锁等动作交给析构函数，可以覆盖所有正常栈展开路径。

## 要解决的问题

手工 open 后在每条路径 close 很容易漏。RAII 把“资源是否需要释放”变成对象生命周期问题。

## 先把几个词说清楚

- **资源**：文件句柄、锁、内存、socket 等需要归还的东西
- **RAII**：资源取得即初始化，把资源责任绑定到对象
- **栈展开**：异常离开函数时依次析构已经创建的局部对象

## 一个案例

writeLog 创建 ofstream，写完直接返回。无论中间是否提前返回，已经构造成功的文件流都会析构。

```cpp
void writeLog() {
    std::ofstream out{"app.log"};
    if (!out) throw std::runtime_error{"open failed"};
    out << "started\n";
} // 自动关闭文件
```

## 常用 API 和作用

| API / 规则 | 用来做什么 |
| --- | --- |
| `std::ofstream` | 析构时关闭文件 |
| `std::lock_guard` | 析构时解锁 mutex |
| `std::unique_ptr` | 析构时释放独占对象 |
| `Rule of Zero` | 优先组合已有 RAII 类型，避免自己写资源管理特殊函数 |

## 怎么验证自己真的理解了

调用 writeLog 后立即重新打开文件读取内容。再在写入前抛异常，确认局部流仍会析构。

## 常见坑

- 析构函数通常不应让异常逃出。
- ofstream 析构会关闭资源，但重要写入仍应显式检查错误。
- RAII 不代表资源无限，仍要缩短对象作用域。

## 马上动手

把一段手写 lock/unlock 的代码改成 lock_guard，并删除所有手动 unlock。

## 学完标准

能解释 RAII 怎样覆盖提前返回和异常路径，并能使用标准 RAII 类型管理资源。
