# 23 · 配置、JSON 与序列化边界

[返回学习地图](../README.md) · [上一篇](22-filesystem与可靠写入.md) · [下一篇](24-C接口ABI与回调.md)

## 先说这篇讲什么

这篇讲怎样使用成熟 JSON 库加载配置，并把格式校验与业务对象创建分开。

## 它有什么用

配置和网络数据来自外部，字段可能缺失、类型错误或版本不兼容。解析成功不等于数据可用。

## 要解决的问题

自己用字符串切割解析 JSON 很快会在转义、嵌套和数字边界上出错。本章示例选择常用的 `nlohmann/json`，并把 `nlohmann::json` 简写成 `Json`。库负责 JSON 语法，业务代码负责字段和范围。

## 先把几个词说清楚

- **解析**：把文本变成 JSON 值
- **校验**：检查必需字段、类型和范围
- **版本字段**：告诉读取方数据采用哪套格式

## 一个案例

服务配置要求 version、port 和 data_file。先解析 JSON，再检查 version 支持、port 在 1–65535、路径非空。

```cpp
Config loadConfig(const Json& value) {
    const int port = value.at("port").get<int>();
    if (port < 1 || port > 65535)
        throw ConfigError{"invalid port"};
    return Config{port};
}
```

## 常用 API 和作用

| API / 规则 | 用来做什么 |
| --- | --- |
| `Json::parse` | 把文本解析成 JSON 结构；语法错误会抛异常 |
| `contains/at/get<T>` | 检查字段、读取字段并转换为指定类型 |
| `dump` | 把 JSON 结构编码成文本 |
| `schema/手工校验` | 明确外部数据必须满足的合同 |

## 怎么验证自己真的理解了

准备正确配置、缺字段、字段类型错、端口越界和未来版本五个输入。每个失败都应指出具体字段。

## 常见坑

- JSON 库只保证语法，不替你保证业务范围。
- 不要把密钥打印进错误日志。
- 写文件仍要使用可靠替换，JSON 本身不保证持久化安全。

## 马上动手

为一个 Config 写字段表：是否必需、默认值、范围和错误信息。

## 学完标准

能把“解析文本”和“验证业务配置”分开，并设计可升级的版本字段。
