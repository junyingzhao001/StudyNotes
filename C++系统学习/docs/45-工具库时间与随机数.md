## 先说这篇讲什么

这篇集中解释 pair、tuple、function、chrono、随机数和 regex 的常见用途与边界。

## 它有什么用

这些工具经常出现在接口和测试中。知道何时使用，比背全部成员函数更重要。

## 要解决的问题

用系统时间测耗时可能受校时影响；用 `%` 处理随机数可能产生偏差；tuple 过大又会让字段含义消失。

## 先把几个词说清楚

- **时间点**：某个时钟上的位置
- **时长**：两个时间点之差
- **分布**：把随机引擎输出映射到需要的范围

## 一个案例

重试策略返回“是否继续”和“等待时长”。正式代码用有名字的 RetryDecision，而不是难读的 tuple<bool, milliseconds>。

```cpp
std::mt19937 engine{seed};
std::uniform_int_distribution<int> dice{1, 6};
const int value = dice(engine);
```

## 常用 API 和作用

| API / 规则 | 用来做什么 |
| --- | --- |
| `pair/tuple` | 返回少量临时组合值；字段多时改用 struct |
| `std::function` | 类型擦除地保存统一签名回调 |
| `steady_clock` | 测耗时和超时 |
| `mt19937 + distribution` | 生成可复现或指定分布的随机值 |

## 怎么验证自己真的理解了

固定 seed 时序列应可复现，换随机种子后可变化。耗时测量使用 steady_clock。

## 常见坑

- 不要用 rand 处理安全需求。
- regex 在复杂文本和大输入上可能慢，先评估边界。
- 捕获很大的 Lambda 放进 std::function 可能发生额外分配。

## 马上动手

写一个带固定种子的重试抖动测试，保证测试结果可重复。

## 学完标准

能选对时间时钟、随机引擎，并知道何时用 struct 代替 tuple。
