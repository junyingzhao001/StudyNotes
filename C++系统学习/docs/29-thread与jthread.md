# 29 · thread、jthread 与线程生命周期

[返回学习地图](../README.md) · [上一篇](28-依赖日志与配置组织.md) · [下一篇](30-mutex与锁范围.md)

## 先说这篇讲什么

这篇讲启动线程后两条执行路线如何同时向前，以及谁负责停止和等待。

## 它有什么用

线程最危险的不是创建语法，而是主线程提前销毁数据、漏 join 或让异常逃出线程入口。

## 要解决的问题

仍可 join 的 std::thread 析构会终止程序。detach 又可能让线程访问已经销毁的局部对象。

## 先把几个词说清楚

- **并发**：多个任务在重叠时间推进
- **join**：等待线程函数结束并回收关联状态
- **停止令牌**：协作通知任务尽快结束，不是强杀线程

## 一个案例

后台循环定期处理任务，main 离开前请求停止。jthread 让等待责任跟对象生命周期绑定。

```cpp
std::jthread worker([](std::stop_token stop) {
    while (!stop.stop_requested()) {
        doOneUnit();
    }
});
```

## 常用 API 和作用

| API / 规则 | 用来做什么 |
| --- | --- |
| `std::thread` | 启动线程，析构前必须 join 或 detach |
| `std::jthread` | 析构时请求停止并 join |
| `joinable/join` | 检查并等待 std::thread |
| `stop_token` | 在线程函数中观察停止请求 |

## 怎么验证自己真的理解了

运行后请求停止并确认程序在限定时间内退出。用纸标出 worker 使用的每个对象必须活到何时。

## 常见坑

- 不要默认 detach；它把生命周期责任变得更难看见。
- 线程函数中的异常若未捕获会终止程序。
- stop request 是请求，任务必须主动检查并退出。

## 马上动手

把一个 thread + bool 停止标志改成 jthread + stop_token。

## 学完标准

能创建、停止并等待线程，并证明线程使用的数据在整个期间都有效。
