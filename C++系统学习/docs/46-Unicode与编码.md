## 先说这篇讲什么

这篇讲字节、码点和用户看到的字符不是同一层，并说明 C++ 字符串默认不替你处理 Unicode。

## 它有什么用

中文文件名、网络 JSON 和界面文本都可能是 UTF-8。按字节截断或计数会出现乱码或错误长度。

## 要解决的问题

一个中文字符通常占多个 UTF-8 字节，带重音符号或 emoji 还可能由多个码点组成。

## 先把几个词说清楚

- **code unit**：编码使用的基本存储单元，例如 UTF-8 字节
- **code point**：Unicode 编号
- **grapheme**：用户通常看到的一个字符单元

## 一个案例

服务限制标题 100 个“用户可见字符”。仅检查 string.size 不够，需要 Unicode 库按 grapheme 计数并限制输入字节总量。

```cpp
std::string text = "你好";
std::cout << text.size(); // 通常是 6 个 UTF-8 字节，不是 2 个字符
```

## 常用 API 和作用

| API / 规则 | 用来做什么 |
| --- | --- |
| `std::string` | 常用于保存 UTF-8 字节，但不懂字符边界 |
| `char8_t/u8string` | 表达 UTF-8 code unit 类型 |
| `成熟 Unicode 库` | 做规范化、大小写、分词和 grapheme 遍历 |
| `filesystem::path` | 处理平台路径，编码规则因平台而异 |

## 怎么验证自己真的理解了

分别记录 ASCII、中文、emoji 和组合字符的字节数、码点数与 grapheme 数。

## 常见坑

- 不要从任意字节位置截断 UTF-8。
- 大小写转换和排序受语言环境影响。
- 编码转换失败必须有明确策略，不能静默丢字节。

## 马上动手

为项目写明内部编码、文件编码、网络编码和非法序列处理策略。

## 学完标准

能解释三种长度的区别，并知道何时必须使用 Unicode 库。
