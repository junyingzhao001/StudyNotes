# 09 · 构造、析构与对象生命周期

[返回学习地图](../README.md) · [上一篇](08-类与封装.md) · [下一篇](10-RAII资源管理.md)

## 先说这篇讲什么

这篇完整追踪对象从创建到销毁的过程，包括成员初始化顺序和不同存储位置的生命周期。

## 它有什么用

文件、锁、连接和内存都依赖对象生命周期管理。知道何时析构，才能判断清理是否及时、引用是否仍有效。

## 要解决的问题

成员并不按初始化列表的书写顺序初始化，而是按类中声明顺序。错误假设可能让一个成员使用尚未准备好的另一个成员。

## 先把几个词说清楚

- **构造函数**：对象创建时建立有效状态
- **析构函数**：对象生命周期结束时执行清理
- **存储期**：决定对象通常能活多久的规则

## 一个案例

Session 在进入大括号时构造，离开大括号时立即析构。用日志观察先构造的成员后析构。

完整文件见 [examples/class_lifecycle.cpp](../examples/class_lifecycle.cpp)。

```cpp
{
    Session session{"database"};
    session.use();
} // 这里调用 session 的析构函数
```

## 常用 API 和作用

| API / 规则 | 用来做什么 |
| --- | --- |
| `成员初始化列表` | 直接初始化成员 |
| `~Type()` | 析构函数 |
| `普通局部对象` | 执行到声明处时创建，离开所在大括号时销毁 |
| `static 局部对象` | 第一次执行到时创建，通常到程序结束才销毁 |
| `thread_local` | 每条线程各有一份对象 |
| `智能指针拥有的动态对象` | 创建时间由程序决定，最后一个所有者释放时销毁 |

## 怎么验证自己真的理解了

创建两个局部 Session A、B，确认析构顺序与构造顺序相反。再把对象移到外层作用域，观察析构时间变化。

## 常见坑

- 不要手动调用普通对象的析构函数。
- 进程被强制终止时不能依赖析构完成重要持久化。
- 名字离开作用域和对象销毁经常同时发生，但引用目标也可能由更外层拥有。

## 马上动手

画出局部对象、static 对象和动态对象的创建与销毁时间线。

## 学完标准

能预测局部对象与成员的构造析构顺序，并区分作用域和生命周期。
