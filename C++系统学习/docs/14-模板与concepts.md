# 14 · 模板、concepts 与编译期多态

[返回学习地图](../README.md) · [上一篇](13-继承与运行时多态.md) · [下一篇](15-string-view与span.md)

## 先说这篇讲什么

这篇讲具体类型在编译时已经知道时，如何复用同一套逻辑，并用约束让错误更好懂。

## 它有什么用

vector、算法和许多库接口都基于模板。能读懂模板参数、实例化和约束，才不会被长报错挡住。

## 要解决的问题

为 int、double 分别复制 larger 会重复逻辑；完全不加约束的模板遇到错误类型时，诊断又可能很长。

## 先把几个词说清楚

- **模板参数**：由调用者提供或由编译器推导的类型/值
- **实例化**：编译器为具体类型生成并检查代码
- **concept**：给模板参数写出可读的能力要求

## 一个案例

clampZero 只接受整数，传入 string 时应在接口处得到清楚错误，而不是在函数体深处报运算符错误。

```cpp
template<std::integral T>
T clampZero(T value) {
    return value < 0 ? 0 : value;
}
```

## 常用 API 和作用

| API / 规则 | 用来做什么 |
| --- | --- |
| `template<typename T>` | 声明类型模板参数 |
| `requires` | 写出约束 |
| `std::integral` | 标准库提供的整数 concept |
| `if constexpr` | 按编译期条件选择分支 |

## 怎么验证自己真的理解了

分别用 int 和 long 调用，再尝试 string。观察错误是否直接指出约束不满足。

## 常见坑

- 模板定义通常要放在使用者可见的头文件中。
- concept 说明语法和类型能力，不自动保证业务语义。
- 不要为了省几行代码把所有接口都改成模板。

## 马上动手

写一个只接受浮点类型的 average 函数，并用 concept 拒绝整数。

## 学完标准

能读懂基本模板、实例化和 concept，并能判断何时用模板、何时用虚函数。
