## 先说这篇讲什么

这篇介绍 C++ Modules、预编译头、编译缓存和增量构建。先理解目标，具体语法以工具链支持为准。

## 它有什么用

大型项目的头文件会被重复解析。Modules 试图提供更明确的导入边界，但编译器和构建系统支持仍需要验证。

## 要解决的问题

为了加快编译盲目使用 unity build 可能隐藏缺失 include 或内部名字冲突。

## 先把几个词说清楚

- **Module**：显式导出和导入名字的编译单元机制
- **预编译头**：提前编译稳定且常用的头文件集合
- **编译缓存**：输入不变时复用之前的编译结果

## 一个案例

先用编译时间报告确认第三方稳定头占主要时间，再评估 PCH；模块实验放独立 target，不影响稳定构建。

```cpp
export module math;
export int add(int left, int right) {
    return left + right;
}
```

## 常用 API 和作用

| API / 规则 | 用来做什么 |
| --- | --- |
| `export module/import` | 声明模块接口和导入模块 |
| `header unit` | 以模块方式导入部分头文件 |
| `PCH` | 项目配置的预编译头 |
| `ccache/sccache` | 按输入缓存编译结果 |

## 怎么验证自己真的理解了

记录干净构建和增量构建时间；更改一个公开接口后确认依赖目标正确重建。

## 常见坑

- Modules 不是 namespace 的替代品。
- 不同编译器的模块构建流程仍可能不同。
- 优化构建前先确保每个头文件自包含。

## 马上动手

生成编译时间报告，找出最慢目标和最重头文件，再决定是否引入 PCH 或模块实验。

## 学完标准

能说明几种构建加速方法的作用和限制，不用技巧掩盖依赖错误。
