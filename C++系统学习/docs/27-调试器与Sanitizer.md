# 27 · 调试器、警告与 Sanitizer

## 先说这篇讲什么

这篇建立固定排错流程：复现、分类、定位、修复、补回归测试。

## 它有什么用

逻辑错误、越界、悬空和数据竞争需要不同工具。工具选对，能找到错误第一次出现的位置。

## 要解决的问题

ASan 不会告诉你业务条件写错，普通断点也不容易发现释放后使用。先分类再选工具。

## 先把几个词说清楚

- **断点**：程序运行到指定位置时暂停
- **调用栈**：当前函数是从哪些函数调用来的
- **Sanitizer**：编译时加入运行检查以发现特定错误

## 一个案例

程序应该找“第一个至少 90”，条件却写成 `> 90`。断点查看 90 时的判断，修成 `>=`，再补边界测试。

```cpp
// 编译内存检查版本
c++ -std=c++20 -fsanitize=address,undefined \
    -fno-omit-frame-pointer -g main.cpp -o app
```

## 常用 API 和作用

| API / 规则 | 用来做什么 |
| --- | --- |
| `LLDB/GDB break/run/next/print` | 暂停、单步和查看变量 |
| `ASan` | 查越界、释放后使用等内存错误 |
| `UBSan` | 查部分未定义行为 |
| `TSan` | 查实际执行路径中的数据竞争 |

## 怎么验证自己真的理解了

分别准备逻辑边界错误和越界 lab。前者用断点与测试，后者用 ASan；记录为什么工具不能互换。

## 常见坑

- 从第一条指向自己代码的诊断开始看。
- Sanitizer 只检查实际走到的路径。
- TSan 与 ASan 通常不能放在同一次构建中。
- 不要修复症状后删除失败输入，要把它变成测试。

## 马上动手

故意制造 vector 越界，用 ASan 找到第一处源码位置并修复。

## 学完标准

能按错误类别选择编译诊断、测试、调试器或 Sanitizer，并留下回归测试。
