# 08 · 类与封装

[返回学习地图](../README.md) · [上一篇](07-指针引用与生命周期.md) · [下一篇](09-构造析构与对象生命周期.md)

## 先说这篇讲什么

这篇讲如何把数据和规则放进一个类，让对象从创建开始就保持有效。

## 它有什么用

类不只是把字段和函数装在一起。它的价值是把修改入口收紧，让调用者不能绕过余额、状态或范围等业务规则。

## 要解决的问题

如果账户余额是公开字段，任何代码都能写入负数。把字段设为 private，并只提供受检查的方法，可以把规则集中在一个地方。

## 先把几个词说清楚

- **封装**：隐藏内部状态，只开放必要操作
- **不变量**：对象活着时始终应满足的规则
- **成员函数**：通过对象调用、能访问对象内部状态的函数

## 一个案例

Account 创建时余额不能为负，withdraw 也不能让余额变成负数。调用者只能通过方法改变余额。

```cpp
class Account {
public:
    explicit Account(int balance) : balance_(balance) {}
    bool withdraw(int amount);
    int balance() const { return balance_; }
private:
    int balance_;
};
```

## 常用 API 和作用

| API / 规则 | 用来做什么 |
| --- | --- |
| `public` | 调用者可以使用的接口 |
| `private` | 只有类自身代码能直接访问 |
| `explicit` | 防止单参数构造函数发生意外隐式转换 |
| `方法末尾 const` | 承诺不通过当前对象修改普通成员 |

## 怎么验证自己真的理解了

构造余额 100 的账户，依次取 30 和 90。第一次应成功并剩 70，第二次应失败且余额不变。

## 常见坑

- 不要机械地为每个字段生成 setter；setter 可能绕过业务规则。
- class 默认 private，struct 默认 public，这只是默认访问级别不同。
- 构造函数也必须检查输入，不能先制造无效对象再等待修复。

## 马上动手

实现 withdraw，并补充“金额必须大于 0”的检查。

## 学完标准

能从类的 public 部分读出合同，并说出 private 状态由哪些规则保护。
