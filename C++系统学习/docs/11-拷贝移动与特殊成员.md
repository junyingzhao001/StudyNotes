# 11 · 拷贝、移动与特殊成员函数

[返回学习地图](../README.md) · [上一篇](10-RAII资源管理.md) · [下一篇](12-智能指针与所有权.md)

## 先说这篇讲什么

这篇讲对象复制和资源转移的区别，以及什么时候让编译器生成、禁止或自定义特殊成员函数。

## 它有什么用

容器扩容、函数返回和对象赋值都会触发拷贝或移动。理解它们可以避免重复释放，也能读懂 `std::move` 后源对象的状态。

## 要解决的问题

拥有裸资源的类若使用默认拷贝，两个对象可能以为自己拥有同一资源，最终重复释放。优先用标准 RAII 成员可避免这类问题。

## 先把几个词说清楚

- **拷贝**：创建内容独立的新对象
- **移动**：把可转移资源交给另一个对象
- **特殊成员函数**：构造、析构、拷贝、移动等编译器可生成的函数

## 一个案例

vector<string> a 复制到 b 后，两边可独立修改；把 a move 给 c 后，c 接管内容，a 仍可析构和重新赋值，但内容不应再假设。

```cpp
std::vector<std::string> a{"one", "two"};
auto b = a;
auto c = std::move(a);
a.clear(); // 移动后的 a 仍可重新使用
```

## 常用 API 和作用

| API / 规则 | 用来做什么 |
| --- | --- |
| `std::move` | 允许后续操作把参数当作可移动对象 |
| `= default` | 明确使用编译器生成版本 |
| `= delete` | 明确禁止某个操作 |
| `Rule of Five` | 手工管理资源时需一起考虑五个特殊成员 |

## 怎么验证自己真的理解了

打印 b、c 的元素。不要把 a 的具体剩余内容写进测试，只验证 a 可以 clear、赋新值和析构。

## 常见坑

- `std::move` 本身不搬数据，它只允许目标操作选择移动。
- 不要为了“性能”把每个返回值都 move；这可能妨碍返回值优化。
- 移动后的对象必须有效，但内容通常只保证满足类型合同。

## 马上动手

写一个禁止复制、允许移动的类型声明，并说明它为什么需要这种限制。

## 学完标准

能区分副本、别名和移动，并知道移动后源对象还能做哪些安全操作。
