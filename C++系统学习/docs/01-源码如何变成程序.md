## 先说这篇讲什么

这篇解释预处理、编译和链接。读完后，看到报错时你能先判断失败在哪一步，而不是从最后一行猜。

## 它有什么用

真实项目有很多 cpp 和库。头文件找不到、类型写错、实现没链接进来会产生不同错误，分类正确才能快速修复。

## 要解决的问题

“构建失败”只是结果。名字未声明属于编译问题，函数只有声明没有实现通常属于链接问题，两者的解决方向完全不同。

## 先把几个词说清楚

- **预处理**：先展开 `#include` 和条件编译
- **编译单元**：一个 cpp 展开头文件后形成的内容
- **链接**：把多个目标文件和库组合成最终程序

## 一个案例

先把函数声明和调用放在 main.cpp，把实现放在 math.cpp。两个文件都参与构建时成功，漏掉 math.cpp 时编译 main.cpp 仍可能成功，但链接会失败。

```cpp
// math.h
int add(int left, int right);

// main.cpp
#include "math.h"
int main() { return add(1, 2) == 3 ? 0 : 1; }
```

## 常用 API 和作用

| API / 规则 | 用来做什么 |
| --- | --- |
| `#include` | 让当前编译单元看到头文件内容 |
| `-c` | 只编译为目标文件，暂不链接 |
| `-o` | 指定输出文件 |
| `undefined reference` | 常见链接错误，通常表示实现没有进入链接 |

## 怎么验证自己真的理解了

分别执行 `c++ -std=c++20 main.cpp math.cpp -o app` 和 `c++ -std=c++20 main.cpp -o app`。记录第二条命令的错误来自编译器还是链接器。

## 常见坑

- `#include "math.cpp"` 不是正常解决链接问题的方法，cpp 应独立编译。
- 一屏报错常由第一处错误连锁产生，先看第一条指向自己源码的诊断。

## 马上动手

故意删掉一个分号，再故意漏掉一个 cpp，分别记录两种错误的关键词。

## 学完标准

能画出 `.cpp → 目标文件 → 可执行文件`，并能区分编译错误和链接错误。
