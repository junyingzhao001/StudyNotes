# 20 · 输入输出流与格式化

[返回学习地图](../README.md) · [上一篇](19-错误模型.md) · [下一篇](21-文本与二进制文件.md)

## 先说这篇讲什么

这篇讲怎样读一整行、再从这一行解析字段，并检查输入是否成功。

## 它有什么用

命令行、配置和文本协议都会遇到空格、坏数字和缺少字段。把“读取”和“解析”分开，一条坏输入不会污染下一条。

## 要解决的问题

直接连续使用 `cin >>` 时，空格会切开标题，失败状态还会让后续读取全部失效。先 getline，再用字符串流解析更可控。

## 先把几个词说清楚

- **流**：按顺序读写数据的对象
- **状态位**：记录上一次读写是否成功
- **格式化**：控制数字、宽度和小数位的输出方式

## 一个案例

命令 `add 42 Learn C++` 先读成一整行，再解析命令名和 id，剩余部分作为标题。

```cpp
std::string line;
std::getline(std::cin, line);
std::istringstream input{line};
std::string command;
int id{};
if (!(input >> command >> id)) return 1;
```

## 常用 API 和作用

| API / 规则 | 用来做什么 |
| --- | --- |
| `getline` | 读取包含空格的整行 |
| `istringstream` | 从 string 中按格式解析 |
| `ostringstream` | 把多段值拼成 string |
| `std::format` | C++20 格式化文本；工具链支持需确认 |

## 怎么验证自己真的理解了

输入正常命令、缺少 id、id 不是数字三种情况，每次都应给出明确提示，不崩溃。

## 常见坑

- 混用 `operator>>` 和 getline 时，前一次留下的换行可能被立即读走。
- 读取失败后要检查或清理流状态，不能继续假设变量有效。
- 面向用户的错误写到 cerr，正常结果写到 cout。

## 学完标准

能把整行输入和字段解析分开，并为坏输入给出可测试结果。
