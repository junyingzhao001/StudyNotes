# 31 · condition_variable 与任务队列

[返回学习地图](../README.md) · [上一篇](30-mutex与锁范围.md) · [下一篇](32-future与promise.md)

## 先说这篇讲什么

这篇讲队列为空时让线程睡眠，并在有任务或需要关闭时可靠醒来。

## 它有什么用

不断轮询会浪费 CPU，单纯 sleep 又增加延迟。条件变量让等待者在状态改变时被通知。

## 要解决的问题

线程可能虚假唤醒，通知也不会替你保存状态。真正决定是否继续的是共享谓词。

## 先把几个词说清楚

- **谓词**：描述现在是否可以继续的条件
- **虚假唤醒**：没有对应业务事件也可能从 wait 返回
- **drain**：停止接收新任务，但处理完已接收任务

## 一个案例

worker 等待 `stopping || !queue.empty()`。若队列有任务就取出；若停止且队列空才退出。

完整的单 worker 队列见 [examples/thread_queue.cpp](../examples/thread_queue.cpp)。

```cpp
cv.wait(lock, [&] { return stopping || !queue.empty(); });
if (stopping && queue.empty()) return;
auto task = std::move(queue.front());
queue.pop();
```

## 常用 API 和作用

| API / 规则 | 用来做什么 |
| --- | --- |
| `condition_variable` | 让线程等待状态变化 |
| `wait(lock, predicate)` | 解锁等待，醒来重锁并检查谓词 |
| `notify_one/all` | 通知一个或全部等待者 |
| `unique_lock` | wait 需要能暂时释放的锁 |

## 怎么验证自己真的理解了

测试先提交后关闭、空队列关闭和多个生产者提交。所有测试要有超时防止永久挂起。

## 常见坑

- 谓词读取的状态和修改该状态通常受同一 mutex 保护。
- 先改状态再通知，通知不是状态本身。
- 不要用 sleep 猜测线程已经运行到某一步。
