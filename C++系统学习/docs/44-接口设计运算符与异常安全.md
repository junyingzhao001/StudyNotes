# 44 · 类接口设计、运算符与异常安全

## 先说这篇讲什么

这篇讲怎样让自定义类型像标准库类型一样自然使用，同时避免隐式转换和失败后的半成品状态。

## 它有什么用

值类型常需要比较、打印或索引。运算符应保持直觉，异常发生后对象至少仍可安全使用。

## 要解决的问题

为了“方便”添加隐式转换或反直觉运算符，会让调用代码在看不见的地方改变类型和成本。

## 先把几个词说清楚

- **值语义**：对象像整数一样可独立复制和比较
- **异常安全保证**：操作失败后对象状态能保证到什么程度
- **noexcept**：声明函数不会让异常逃出

## 一个案例

TaskId 包装 int，防止把用户 id 与任务 id 混用；它支持相等比较，但不提供与 int 的隐式互转。

```cpp
class TaskId {
public:
    explicit TaskId(int value) : value_(value) {}
    auto operator<=>(const TaskId&) const = default;
private:
    int value_;
};
```

## 常用 API 和作用

| API / 规则 | 用来做什么 |
| --- | --- |
| `operator== / <=>` | 定义相等和排序关系 |
| `operator[] / at` | 不检查/检查边界访问 |
| `explicit 转换` | 要求调用者明确写出类型变化 |
| `noexcept` | 帮助调用者和容器选择安全移动路径 |

## 怎么验证自己真的理解了

确认 TaskId 可比较，但 `TaskId id = 7` 编译失败，必须写 `TaskId{7}`。

## 常见坑

- 运算符含义应符合常识，不要让 + 修改左侧对象。
- 只有真正不会抛异常的函数才写 noexcept。
- 强异常保证常用“先准备新状态，成功后再交换”。

## 马上动手

## 学完标准
