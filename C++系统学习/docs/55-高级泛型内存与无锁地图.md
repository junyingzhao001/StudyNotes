# 55 · 高级泛型、内存与无锁结构地图

[返回学习地图](../README.md) · [上一篇](54-Modules与大型构建.md)

## 先说这篇讲什么

这篇不是要求立即实现高级设施，而是给出阅读模板库、内存资源和无锁代码时的路线图。

## 它有什么用

基础设施项目会出现完美转发、type traits、PMR、原子 CAS 和 ABA。先知道每项解决什么，再决定是否深入。

## 要解决的问题

这些技术很容易制造“看起来高级”的复杂代码。没有真实需求、测试和测量时，标准容器与锁通常更可靠。

## 先把几个词说清楚

- **type trait**：在编译期查询或变换类型信息
- **完美转发**：尽量保留实参的左值/右值性质
- **ABA**：CAS 看到值恢复原样，却不知道中间发生过变化

## 一个案例

高频临时对象导致分配成为已测量热点时，可用 monotonic_buffer_resource 做批量生命周期内存；作用域结束整体释放。

```cpp
std::array<std::byte, 4096> storage;
std::pmr::monotonic_buffer_resource resource{storage.data(), storage.size()};
std::pmr::vector<int> values{&resource};
```

## 常用 API 和作用

| API / 规则 | 用来做什么 |
| --- | --- |
| `std::forward` | 在转发引用中保留值类别 |
| `type_traits` | 编译期类型判断与变换 |
| `std::pmr` | 让容器使用可替换内存资源 |
| `compare_exchange` | 构建无锁算法的基础操作之一 |

## 怎么验证自己真的理解了

先用普通 allocator 建立正确性基线，再测量 PMR 版本的分配次数和总耗时；资源必须活得比容器久。

## 常见坑

- 完美转发只应出现在真正的通用转发层。
- PMR 改变分配来源，不自动减少对象数量。
- 无锁不等于更快，也不等于无需内存回收协议。

## 马上动手

从实际项目挑一段高级代码，为每个模板或原子操作写出它解决的具体需求；没有需求的先不模仿。

## 学完标准

能识别高级工具的用途和风险，并知道需要哪些前置知识、测试和性能证据。
