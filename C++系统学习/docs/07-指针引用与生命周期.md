# 07 · 指针、引用与生命周期

[返回学习地图](../README.md) · [上一篇](06-宏与条件编译.md) · [下一篇](08-类与封装.md)

## 先说这篇讲什么

这篇讲对象、引用和指针之间的关系。核心不是记星号，而是每次都确认谁拥有对象、对象何时销毁。

## 它有什么用

C API、系统库、容器和性能敏感代码大量使用地址或借用。生命周期判断错误会产生悬空指针，程序可能偶尔正常、偶尔崩溃。

## 要解决的问题

指针只保存地址，不会自动让目标继续存活。函数返回局部变量地址后，地址数值可能还在，但对象已经不存在。

## 先把几个词说清楚

- **拥有者**：负责让对象存在并最终销毁它的代码
- **借用**：暂时访问别人拥有的对象
- **悬空**：地址或引用仍在，但目标生命周期已经结束

## 一个案例

findTask 找不到任务时返回 nullptr，找到时返回容器中元素的地址。调用者可以检查空值，但不能让指针活过容器或元素。

```cpp
Task* findTask(std::vector<Task>& tasks, int id) {
    for (auto& task : tasks)
        if (task.id == id) return &task;
    return nullptr;
}
```

## 常用 API 和作用

| API / 规则 | 用来做什么 |
| --- | --- |
| `&value` | 取得对象地址 |
| `*pointer` | 访问指针指向的对象 |
| `nullptr` | 明确表示当前不指向对象 |
| `T* / const T*` | 可修改/只读的可空借用 |

## 怎么验证自己真的理解了

分别查找存在和不存在的 id。随后阅读 vector 失效规则，解释为什么继续 push_back 后不应盲目使用旧指针。

## 常见坑

- 不要解引用 nullptr。
- 不要返回局部对象的地址或引用。
- vector 扩容可能搬动元素，使旧指针和引用失效。
- 指针是 const 还是目标是 const，要分别看星号两侧。

## 马上动手

为一段包含局部对象、引用和指针的代码画时间线，标出每个借用的有效终点。

## 学完标准

每次使用指针前都能回答“可能为空吗、指向谁、目标现在还活着吗”。
