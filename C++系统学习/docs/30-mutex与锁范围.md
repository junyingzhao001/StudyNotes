# 30 · mutex 与锁范围

[返回学习地图](../README.md) · [上一篇](29-thread与jthread.md) · [下一篇](31-条件变量与任务队列.md)

## 先说这篇讲什么

这篇讲用互斥锁保护共享状态，以及为什么锁要覆盖完整业务不变量。

## 它有什么用

两个线程无同步地读写同一内存会产生数据竞争，程序行为不再可靠。锁把相关操作变成一次受保护的临界区。

## 要解决的问题

分别锁住“检查余额”和“扣款”仍可能让两条线程都通过检查。检查和修改必须在同一把锁下完成。

## 先把几个词说清楚

- **数据竞争**：多个线程无同步访问同一位置且至少一方写
- **临界区**：持锁访问共享状态的代码范围
- **死锁**：线程互相等待对方持有的锁

## 一个案例

账户 transfer 同时锁住两个账户，再检查和修改余额；输出日志放到解锁后，减少持锁时间。

```cpp
std::scoped_lock lock{from.mutex_, to.mutex_};
if (from.balance_ < amount) return false;
from.balance_ -= amount;
to.balance_ += amount;
```

## 常用 API 和作用

| API / 规则 | 用来做什么 |
| --- | --- |
| `mutex` | 提供互斥访问 |
| `lock_guard` | 作用域内持锁，离开自动解锁 |
| `unique_lock` | 可延迟、暂时解锁，条件变量需要它 |
| `scoped_lock` | 一次安全取得多把锁 |

## 怎么验证自己真的理解了

多线程重复转账，最终总余额必须保持不变。再用 TSan 运行一次。

## 常见坑

- 所有访问共享状态的路径都要遵守同一同步规则，包括只读。
- 不要在持锁时做网络或慢文件 I/O。
- 多把锁要使用统一顺序或 scoped_lock。

## 马上动手

为一个共享计数和一个跨字段状态分别标出锁保护的不变量。

## 学完标准

能定义“哪把锁保护哪些数据”，并让检查与修改处于同一临界区。
