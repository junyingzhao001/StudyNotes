# 13 · 继承与运行时多态

[返回学习地图](../README.md) · [上一篇](12-智能指针与所有权.md) · [下一篇](14-模板与concepts.md)

## 先说这篇讲什么

这篇讲调用者只依赖一个稳定接口，实际对象在运行时可以替换的情况。

## 它有什么用

存储后端、渲染对象、策略插件等场景需要统一调用方式。虚函数让基类引用或指针调用到实际派生实现。

## 要解决的问题

按值把派生对象复制到基类会发生对象切片，派生部分丢失。通过基类指针销毁派生对象时还需要虚析构。

## 先把几个词说清楚

- **基类**：定义共同接口的类型
- **派生类**：提供具体实现的类型
- **虚分派**：运行时根据真实对象选择 override 实现

## 一个案例

TaskStore 是接口，MemoryStore 和 FileStore 分别把任务放在内存和文件中。业务代码只依赖 TaskStore。

```cpp
class TaskStore {
public:
    virtual ~TaskStore() = default;
    virtual void save(const Task& task) = 0;
};
```

## 常用 API 和作用

| API / 规则 | 用来做什么 |
| --- | --- |
| `virtual` | 让方法参与运行时分派 |
| `= 0` | 纯虚函数，使类成为抽象接口 |
| `override` | 让编译器检查确实覆盖了基类方法 |
| `virtual ~Base()` | 允许通过基类指针正确销毁派生对象 |

## 怎么验证自己真的理解了

用 `unique_ptr<TaskStore>` 分别持有两个实现，调用相同的 save，确认进入不同实现。

## 常见坑

- 优先组合；只有“派生对象确实是一种基类”并需要替换实现时才用继承。
- 不要删除 override 来掩盖签名不匹配。
- 多态对象通常通过引用或智能指针使用，避免切片。

## 马上动手

增加一个只记录调用次数的 FakeStore，用它测试业务逻辑是否调用了 save。

## 学完标准

能实现带虚析构的抽象接口，并通过基类智能指针安全使用派生对象。
