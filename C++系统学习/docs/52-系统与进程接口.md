# 52 · 系统与进程接口

## 先说这篇讲什么

这篇建立操作系统边界地图：参数、环境变量、信号、进程、管道、动态加载和内存映射。

## 它有什么用

标准 C++ 只覆盖其中一部分。真实系统程序需要平台 API 或跨平台库，并把它们隔离在适配层。

## 要解决的问题

在信号处理函数里调用普通日志或分配内存通常不安全；fork、handle 和文件描述符也有平台差异。

## 先把几个词说清楚

- **进程**：拥有独立地址空间的运行程序
- **管道**：进程间按字节传输数据的通道
- **文件描述符/handle**：操作系统资源的整数或句柄标识

## 一个案例

主程序只依赖 ProcessRunner 接口；Linux 和 Windows 分别实现启动子进程、捕获输出和超时终止。

```cpp
class ProcessRunner {
public:
    virtual ~ProcessRunner() = default;
    virtual Result run(const Command&, Timeout) = 0;
};
```

## 常用 API 和作用

| API / 规则 | 用来做什么 |
| --- | --- |
| `argc/argv` | 读取命令行参数 |
| `getenv/配置库` | 读取环境变量 |
| `signal/process API` | 平台相关的信号和进程控制 |
| `mmap/MapViewOfFile` | 把文件区域映射到虚拟内存 |

## 怎么验证自己真的理解了

测试正常退出、非零退出、超时和不存在的程序。确保所有管道和进程句柄最终关闭。

## 常见坑

- 系统调用可能被中断或只处理部分数据。
- 不要在信号处理函数做复杂工作，常见做法是设置安全标志或写入专用管道。
- 平台资源也要用 RAII 包装。

## 马上动手

列出项目直接调用的系统 API，并把它们收拢到一层接口后面。

## 学完标准

能识别标准 C++ 与平台 API 的边界，并为系统资源设计 RAII 和错误合同。
