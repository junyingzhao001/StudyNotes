# 21 · 文本与二进制文件

[返回学习地图](../README.md) · [上一篇](20-流与格式化.md) · [下一篇](22-filesystem与可靠写入.md)

## 先说这篇讲什么

这篇讲文件怎样打开、读写和报告失败，同时区分文本记录与二进制字节。

## 它有什么用

文件打开成功不代表后续写入一定成功。可靠代码要检查路径、格式、写入和关闭边界。

## 要解决的问题

只判断文件对象构造成功，就宣称“保存完成”，可能在磁盘满或刷新失败时丢数据。

## 先把几个词说清楚

- **文本模式**：内容按字符和行解释
- **二进制模式**：把内容当原始字节
- **缓冲**：先暂存在内存，再批量交给系统

## 一个案例

任务文件每行保存 id、完成状态和带引号标题；读取时逐行解析，任何坏行都报告行号。

完整文件见 [examples/file_tasks.cpp](../examples/file_tasks.cpp)。

```cpp
std::ofstream out{path};
if (!out) throw std::runtime_error{"cannot open"};
out << id << ' ' << std::quoted(title) << '\n';
out.close();
if (!out) throw std::runtime_error{"write failed"};
```

## 常用 API 和作用

| API / 规则 | 用来做什么 |
| --- | --- |
| `ifstream` | 只读文件流 |
| `ofstream` | 只写文件流 |
| `fstream` | 可读写文件流 |
| `ios::binary/app/trunc` | 二进制、追加、截断等打开方式 |

## 怎么验证自己真的理解了

测试正常路径、父目录不存在、目标不可写和文件中有坏行。成功与失败都检查输出及退出码。

## 常见坑

- eof 只有尝试越过末尾后才会设置，常用 `while (getline(...))`。
- 不要把含指针或填充字节的对象直接写成二进制文件。
- 析构会关闭文件，但重要持久化要显式检查最终状态。

## 马上动手

实现保存和加载两条路径，并让加载错误包含文件名和行号。

## 学完标准

能正确检查打开、读写和关闭结果，并解释文本与二进制格式的差别。
