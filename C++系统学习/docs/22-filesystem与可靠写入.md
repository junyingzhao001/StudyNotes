# 22 · filesystem 与可靠写入

## 先说这篇讲什么

这篇讲跨平台处理路径、目录和文件替换，并用临时文件避免写坏原文件。

## 它有什么用

直接拼接斜杠会遇到平台差异；直接覆盖原文件时，程序中途失败可能同时失去旧数据和新数据。

## 要解决的问题

保存配置若先清空原文件再写，磁盘错误或进程退出会留下半个文件。先写同目录临时文件，再 rename，风险更小。

## 先把几个词说清楚

- **path**：按平台规则保存路径组成部分的类型
- **原子替换**：观察者只看到旧文件或新文件，不看到中间一半
- **error_code**：不抛异常地接收文件系统错误

## 一个案例

保存 tasks.db 时先写 tasks.db.tmp，确认成功后再替换正式文件。临时文件必须与目标在同一文件系统。

```cpp
auto temp = target;
temp += ".tmp";
writeAll(temp, data);
std::filesystem::rename(temp, target);
```

## 常用 API 和作用

| API / 规则 | 用来做什么 |
| --- | --- |
| `filesystem::path` | 组合和拆分路径 |
| `exists/create_directories` | 检查并创建目录 |
| `rename` | 移动或替换文件，具体语义需看平台 |
| `remove` | 删除文件或空目录 |

## 怎么验证自己真的理解了

在写临时文件后故意失败，确认原文件仍完整；正常路径再确认新内容生效。

## 常见坑

- 当前工作目录决定相对路径起点。
- rename 是否覆盖已有文件有平台差异，生产代码要验证目标平台。
- 检查 exists 后再操作仍可能被其他进程改变，必须处理最终操作错误。

## 马上动手

实现 `safeSave(path, data)`，为成功、临时写失败和替换失败写测试。

## 学完标准

能用 path 组合路径，并解释临时文件加替换为什么比直接覆盖可靠。
