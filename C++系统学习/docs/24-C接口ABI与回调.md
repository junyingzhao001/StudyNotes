## 先说这篇讲什么

这篇讲怎样在 C++ 与 C、系统库或 JNI/NDK 边界传递数组、字符串和回调。

## 它有什么用

边界接口通常只给地址和长度，不知道容器、异常或智能指针。调用双方必须明确所有权、长度和回调有效期。

## 要解决的问题

只传 `int*` 看不出有多少元素；把 C++ 异常穿过 C ABI 也没有可靠合同。

## 先把几个词说清楚

- **ABI**：编译后函数名、参数布局等二进制约定
- **指针+长度**：用地址和数量描述连续数据
- **context 指针**：把调用者状态传回 C 回调的通用做法

## 一个案例

C 接口接收 `const int* data, size_t size`。C++ 包装层立即转为 span，检查空地址和长度，再进入业务逻辑。

```cpp
extern "C" int sum_values(const int* data, size_t size) {
    if (!data && size != 0) return -1;
    return sum(std::span{data, size});
}
```

## 常用 API 和作用

| API / 规则 | 用来做什么 |
| --- | --- |
| `extern "C"` | 使用 C 链接规则导出函数 |
| `data/size` | 从连续容器取得地址和元素数 |
| `callback + void*` | C 风格回调与上下文 |
| `span` | 在 C++ 内部把地址和长度包装成安全视图 |

## 怎么验证自己真的理解了

测试空范围、正常数组和空指针加非零长度。不要让异常离开 extern C 函数。

## 常见坑

- size 的单位必须写清是元素还是字节。
- C 字符串要求 `\0` 结尾，string_view 不保证。
- 回调可能晚于注册函数返回，要保证 context 仍然存活。

## 马上动手

为一个 C 数组接口写 C++ span 包装，并列出所有权和错误码合同。

## 学完标准

能安全处理指针、长度和回调生命周期，并知道异常不能随意跨 C ABI。
