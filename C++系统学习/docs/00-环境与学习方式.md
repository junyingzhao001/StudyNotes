## 先说这篇讲什么

这篇先把学习方式和工具准备好。读完后，你能编译、运行并判断一个程序是否成功结束。

## 它有什么用

C++ 不是把源码直接交给运行时执行，而是先生成本机程序。后面所有示例都依赖这一步，先跑通能避免把环境问题误认为语法问题。

## 要解决的问题

新手常看到一长串编译命令就开始背参数。真正要做的是分清源码、生成的程序和运行结果，并保留一条稳定的验证命令。

## 先把几个词说清楚

- **源码**：你写的 `.cpp` 文本
- **编译器**：把源码翻译成本机程序的工具
- **退出码**：程序结束时交给系统的数字，0 通常表示成功

## 一个案例

下面的程序只做一件事：打印一句话并正常结束。先关注“能否稳定复现”，暂时不用记住每个符号。

完整文件见 [examples/00_hello.cpp](../examples/00_hello.cpp)。

```cpp
#include <iostream>

int main() {
    std::cout << "C++ is ready\n";
    return 0;
}
```

## 常用 API 和作用

| API / 规则 | 用来做什么 |
| --- | --- |
| `c++ --version` | 确认编译器存在 |
| `-std=c++20` | 按 C++20 规则编译 |
| `-Wall -Wextra -Wpedantic` | 让编译器多提醒可疑代码 |
| `-g` | 保留调试信息 |

## 怎么验证自己真的理解了

把代码保存为 `hello.cpp`，执行 `c++ -std=c++20 -Wall -Wextra -Wpedantic -g hello.cpp -o hello`，再运行 `./hello`。应看到 `C++ is ready`，随后 `echo $?` 应输出 0。

## 常见坑

- 终端的工作目录决定相对路径从哪里开始，不是源码所在目录自动决定。
- 只看到程序有输出还不够；自动化脚本还会检查退出码。

## 马上动手

亲手输入一次编译和运行命令，再把 `return 0` 改成 `return 2`，观察退出码变化。

## 学完标准

不看文档也能从一个 `.cpp` 生成程序、运行它，并说出源码、可执行文件和退出码分别是什么。
