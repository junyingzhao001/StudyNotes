# 项目三：TCP 任务服务

## 这个项目练什么

把 Asio、消息分帧、超时、类生命周期、任务执行器、文件持久化、日志和集成测试连起来。

## 协议

每条消息使用“4 字节大端长度 + UTF-8 JSON 正文”。正文最大 1 MiB。请求必须带 `request_id` 和 `command`，响应原样返回 `request_id`。

```json
{"request_id":1,"command":"add","title":"Learn C++"}
```

## 模块边界

- `Session`：只处理连接、分帧、超时和响应队列。
- `Protocol`：JSON 与命令对象互转，负责字段校验。
- `TaskService`：实现 add、done、remove、list 规则。
- `Repository`：保存和加载任务。
- `Executor`：运行阻塞文件操作。

## 实现顺序

1. 先完成并测试 TaskService。
2. 完成长度前缀编码器和增量解析器。
3. 实现单连接同步版本。
4. 改成 Asio 异步 Session，并加入单一写队列。
5. 加入读超时、最大包长、关闭和日志。
6. 最后加入多连接、持久化和优雅关闭。

## 必测场景

- 正常请求、未知命令、缺字段和坏 JSON。
- 长度头被拆开、正文被拆开、两条消息粘在一起。
- 超大长度、慢客户端、半包后断线。
- 多客户端并发添加任务。
- 保存失败时不提交内存状态。
- 服务停止后不再接受连接，已有响应有明确完成或取消结果。

## 完成标准

业务、协议和网络层能分别测试；每条连接有内存与时间上限；关闭顺序可以画成时序图并由集成测试验证。
